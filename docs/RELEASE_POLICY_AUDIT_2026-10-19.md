# 출시 정책·법적 위험·운영 준비 점검 · 2026-10-19

## 결론과 점검 범위

**모두 동기화됐다고 판정할 수 없다.** 방침 원문과 주요 개인정보 선언은 상당 부분 맞지만, 콘텐츠 등급 설문 재검토, 광고 승인·등급 설정, 상품 설명 및 출시본 검증이 남아 있다. 아래 미확인 사항을 통과로 취급하지 않는다.

이 문서는 코드·공식 문서·콘솔 화면을 대조한 출시 점검이다. 변호사/법무사의 정식 법률의견이나 적법성 보증이 아니다. 국내 개인정보 국외 이전, 미성년자 결제, 사업자 의무는 실제 사업 형태와 계약을 바탕으로 전문가 확인이 필요하다.

- 소스 기준: `feat/ui-first-release`, `519d717`, 앱 0.76.32. 읽기 전용 원격 갱신 후 원격 UI 브랜치와 0/0, 시작 시 작업 폴더 깨끗함.
- 콘솔 기준: Google Play 비공개 Alpha 배포본은 **76025 / 0.76.25**. 내부 테스트는 **62001 / 0.62.1**. 최신 UI 소스와 같은 버전이 아니다.
- 대상: 게임 소스, Git 추적 파일, 공개 개인정보처리방침, Play Console 선언·상품·출시 현황, AdMob 상태. 콘솔은 읽기만 수행했다.
- 제외: Firebase/Cloud 자원·서버 브랜치 변경, 실제 결제·광고 보상 실행, 실제 사용자 저장 변경, AAB 업로드, 정책 제출·수정.
- 기록한 변경은 이 보고서와 작업일지·검증결과·CONTINUE뿐이다. 앱 0.76.32, 저장42, 방침12, 약관9 유지.

은행에 비유하면 게임 화면은 창구, 공개 방침은 약관 게시판, Play 선언은 감독기관에 낸 신고서다. 게시판 내용이 일치해도 창구 상품 설명과 신고서가 오래됐으면 전체 점검을 통과한 것이 아니다.

용어: **SDK**는 광고·결제를 넣기 위해 사용하는 외부 개발 도구다. **IARC**는 콘텐츠 질문에 답해 지역별 이용등급을 받는 체계다. **AAB**는 Play에 올리는 안드로이드 배포 파일이다. **비공개 테스트**는 지정된 이용자에게만 앱을 배포하는 단계다.

## 1. 시간 순서로 수행한 일

1. 저장소 작업 규칙, 브랜치, 원격 차이, 버전, 기존 출시·권리·정책 문서를 읽었다. 서버 작업은 재개하지 않았다.
2. 나이·필수 동의·광고 선택·약관·방침, Android 광고/결제 코드, 저장·오류 기록·상품 및 캠페인 정의를 대조했다.
3. Play Console의 앱 콘텐츠 선언, 타겟층, 등급 상세, 데이터 보안 입력/미리보기, 정책 URL, 테스트 현황, 국가, 상품 2종을 읽었다. 저장·제출·구매하지 않았다.
4. 공개 방침의 보이는 본문을 앱 원문과 비교했다. 원문 34개 문단 모두 포함됐고 Git의 방침 문서도 소스 생성 결과와 일치했다.
5. AdMob의 계정 승인, 앱 검토, 스토어 연결, 정책센터, 계정 광고 콘텐츠 등급을 읽었다. 등급 설정 화면은 취소로 나왔고 값을 바꾸지 않았다.
6. 공식 Google 정책, 한국 법령, 음원 상업 이용 안내와 대조했다. 전투 소스 재확인 후 병사 직접 사격 중심이라는 초기 설명을 정정했다. 현재 전투는 군사 장비 교전 중심이다.
7. 전체 테스트·일반 웹 빌드·출시용 자산 검사·운영 npm 의존성 취약점 검사를 실행했다. 오류 기록의 개인정보 가림 부재를 가짜 값과 메모리 저장만으로 재현했다.
8. 스토어 등록정보의 현재 게시/초안 상태와 편집 화면 문구를 읽었다. 기존 초안을 수정하거나 제출하지 않았다.
9. 확인된 결과와 미확인을 분리해 문서화했다. 외부 콘솔 원문·계정 이메일·결제/개발자 식별번호·토큰은 저장소에 넣지 않았다.

일부 브라우저 진입에서 지연/대상 메뉴 없음이 있어 현재 화면을 다시 확인하고 읽기 탐색을 계속했다. 설정 저장이나 권한 변경으로 우회하지 않았다. 소스 검색 경로가 맞지 않는 경우 실제 파일 목록으로 정정했다. 출시 빌드 실패는 아래 원인을 확인했으며 음원을 임의로 만들어 대체하거나 검사를 무력화하지 않았다.

## 3. 출시 전에 우선 해결할 사항

### A. 콘텐츠 등급 설문을 현재 전투로 재검토

**직접 확인함:** IARC 상세는 비인간 대상 폭력으로 표시된다. 현재 전투 소스는 전차·헬기 등 군사 장비가 공격하고 피해를 받는 구조다. 병사 직접 사격 중심이라고 처음 설명한 부분은 소스 재확인 후 정정했다.

**공식 문서로 확인함:** Google은 사람이 탔을 것으로 보이는 차량 공격도 사람에 대한 간접 폭력 예로 설명한다. 픽셀 그림이나 허구라는 이유만으로 제외할 수 없다. 현재 장비가 사람 없는 로봇으로 분명하게 표현되는지, 유인 장비로 보이는지 등 실제 장면을 기준으로 답해야 한다. 임의로 12세/15세 등급을 정해 올리라는 뜻이 아니다.

**다음 작업:** 실제 전투·장비 파괴 장면을 기준으로 질문별 답변 근거를 만들고, 사용자 확인 후 설문을 재제출할지 결정한다. 이번에는 제출하지 않았다.

근거: [사람을 향한 폭력](https://support.google.com/googleplay/android-developer/answer/6160464?hl=ko), [콘텐츠 등급](https://support.google.com/googleplay/android-developer/answer/9859655?hl=ko).

### B. 실제 광고를 켜기 전 준비

- **직접 확인함:** AdMob 계정/앱 승인 미완료, 소스는 테스트 ID. 소스는 청소년G·성인T 요청. 계정 기본은 MA.
- **공식 문서로 확인함:** 광고 요청에 지정한 SDK 등급 한도는 AdMob 화면의 한도를 재정의한다. 콘솔만 G로 바꾸고 성인T 코드를 그대로 두는 것은 충분하지 않다. 게임의 최종 콘텐츠 등급에 맞는 광고를 제공하도록 요청 설정까지 함께 점검해야 한다.
- **미확인:** 출시 AAB의 실제 요청 설정, 동의 전/거부 후 데이터 전송, 앱별 별도 등급, 광고 범주·URL 차단, app-ads.txt 인증, 실제 보상 광고의 완료/취소 동작.
- **권고:** 최종 게임 등급 확정 → 코드·계정·앱 설정 대조 → 승인/스토어 연결 → 테스트 기기로 통신·보상 검증 → 실ID 전환. 승인 전 수익이 발생한다고 안내하지 않는다.

근거: [AdMob 등급 우선순위](https://support.google.com/admob/answer/7562142?hl=ko), [광고 SDK 데이터 공개](https://developers.google.com/admob/android/privacy/play-data-disclosure).

### C. 결제 설명·실제 구매·환불 운영

**직접 확인함:** 자동터치 초당10회와 Play 설명5회 불일치. 현재 코드에는 Google Play Billing 연결이 있고 출시 결제는 명시적인 빌드 설정이 필요하다. '결제 미구현'이라고 남은 문서를 그대로 쓰면 안 된다. 반대로 최신 코드에 연결이 있다고 실제 AAB에서도 결제가 켜져 있다고 단정할 수 없다.

좋은 장치: Play에서 받은 실제 가격 표시, 구매 완료 상태·상품·패키지·서명 확인, 중복 처리 방지, 저장 성공 뒤 구매 확인 처리, 대기/취소 시 미지급, 자동터치 복원, 개발용 무료 지급의 출시 차단.

남은 위험:

- 현재 검증이 주로 기기 안에서 실행된다. 변조·환불/취소 후 권한 회수·여러 기기의 악용을 서버 검증과 같은 수준으로 막는 것은 아니다. 이는 곧바로 정책 위반이라는 뜻은 아니며, 첫 출시 서버 제외 결정도 이번에 변경하지 않는다.
- Google 실시간 구매 변경 알림을 처리하는 서버가 없으므로 환불 문의 대응, 재접속 확인, 권한 복구/정리 범위를 정하고 문서화해야 한다.
- 스타터팩은 재설치/다른 기기에서 보상이 다시 지급될 수 있다는 현재 안내·설계가 있다. 영구 자동터치 복원과 소모품/게임 진행 복원을 혼동시키지 않아야 한다.
- **미확인:** Play 라이선스 테스트 계정으로 성공·취소·대기·중복 콜백·앱 강제 종료·저장 실패·복원·환불·두 기기 시험. 이번 감사에서는 결제를 실행하지 않았다.
- 환불/청약철회·미성년자 취소권을 '디지털 상품이라 일절 불가'로 제한하면 안 된다. 상품별 소비 시작, 사전 고지, 취소/환불 가능 범위를 실제 판매 방식에 맞춰 법률 검토한다.

근거: [결제 보안 권고](https://developer.android.com/google/play/billing/security), [민법 제5조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1026990807).

### D. 한국 사업자·미성년자·국외 이전 확인

**사업자 — 미확인:** 사업자 등록/통신판매 관련 의무의 적용, Play 한국 개발자 필수 판매자 정보, 실제 연락 수단·문의 대응 체계. 유료 판매를 한다면 개발자 계정 인증만으로 충분하다고 볼 수 없다. 필요한 등록/신고 및 면제 여부를 실제 사업 형태로 확인하고 콘솔 필수 항목과 대조한다. 등록번호·개인 연락처를 채팅/공개 Git에 넣지 않는다. [한국 개발자 요건](https://support.google.com/googleplay/android-developer/answer/6223646?hl=ko).

**미성년자 — 소스 확인 / 운영 미확인:** 약관은 법정대리인 동의와 미성년자 취소 보호를 안내한다. 하지만 나이 입력/체크만으로 구매에 대한 법정대리인 동의를 입증하는 것은 아니다. 만14세 개인정보 동의 기준과 민법상 성년19세를 혼동하지 않는다. 법정대리인 문의·취소 처리 절차를 준비한다. Play 타겟층 구간과 이용등급은 각각 별개 판단이다.

**나이 입력 — 검토 필요:** 입력값을 미리 채우지 않는 점은 좋다. 다만 화면이 '만14세 이상'이라고 답의 기준을 알려준다. 중립적 나이 확인이 요구되는 경우 적합한지 실제 타겟층·광고 처리에 맞춰 검토해야 한다. 이번 감사로 무조건 위반이라고 판정하지 않는다. [타겟층 및 콘텐츠](https://support.google.com/googleplay/android-developer/answer/9867159).

**국외 이전 — 문구 직접 확인 / 법적 근거 미확인:** 현행 방침은 'Google 서버/해외 서버' 수준의 안내다. 실제 계약상 수령자, 국가, 이전 항목·목적·방법/시점, 보유기간, 적용 법적 근거와 거부 시 영향이 충분한지 확인해야 한다. 별도 동의만이 유일한 근거는 아니므로 임의로 동의 항목만 추가해 해결했다고 하지 않는다. 기존 `docs/store/PRIVACY_RELEASE_REVIEW.md`에도 후속 검토가 남아 있다. [개인정보보호법 제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029331957).

**데이터 보안 — 선언 대조 완료 / 실제 전송 미확인:** 선택 광고 거부자는 광고 SDK 전송을 하지 않는지, 동의 철회 후 멈추는지 실제 기기에서 확인해야 '선택 수집' 선언을 뒷받침할 수 있다. 비맞춤 광고도 개인정보 처리가 전혀 없다는 뜻은 아니다. 구매 공유 제외는 사용자 요청에 따른 전송 등 Google 정의를 근거로 평가해야 하며 'Google이 받지 않는다'는 뜻이 아니다. [데이터 보안 작성 기준](https://support.google.com/googleplay/android-developer/answer/10787469).

### E. 오류 기록의 민감정보 가림 보강

**직접 재현함:** `src/error-log.js`와 `src/diagnostics.js` 경로에 가짜 이메일·가짜 token 쿼리를 넣은 오류를 메모리에서 처리하면 문의용 출력에 그대로 남는다. 길이 제한/HTML 이스케이프는 개인정보 가림과 다르다.

실제 토큰 유출이 발생했다는 증거는 없다. 결제 코드 자체의 별도 정제 처리도 존재한다. 그러나 향후 외부 도구 오류를 그대로 기록할 경우 위험하다. 저장 전과 복사 전 공통 가림을 적용하고 가짜 값으로 회귀 테스트를 추가하는 것을 권고한다. 사용자 실제 오류 기록은 이번에 열거나 전송하지 않았다.

| 공개 방침 대조 | 34/34 원문 문단 포함, Git 생성본 일치 |
| 오류 가림 재현 | 가짜 민감 문구가 문의용 보고서에 남음. 실제 비밀 사용/저장 없음 |
| 실제 출시 AAB | 이번에 새로 빌드·설치·결제·통신 시험하지 않음 |

음악 누락은 이 작업 폴더의 출시 빌드 차단 사유다. **이미 업로드된0.76.25에 음악이 없다는 증거가 아니다.** 이전 AAB의 자산/서명 검증은 과거 문서로만 확인했다. 현재 웹 빌드 성공을 Android 출시 준비 완료로 바꾸어 말하지 않는다.

원시 콘솔 출력/외부 문서 사본/임시 검증 로그는 저장소 밖 작업 영역에 두고 Git에 추가하지 않았다. 기록에 이메일·숫자 계정ID·결제번호·인증 토큰을 남기지 않았다. 공개 문서 URL도 여기서는 계정 식별 정보 대신 저장소의 기존 정책 설정을 기준으로 설명한다.

## 9. 다음 단계와 되돌림

**다음 한 단계: 콘텐츠 등급 설문을 실제 전투 장면 기준으로 재검토하는 표부터 작성한다.** 사용자 확인 전 콘솔 제출은 하지 않는다. 이어서 상품 설명, 광고 설정/승인, 개인정보/사업자 미확인 사항, 출시 후보 실기기 검증 순으로 처리한다.

이번에는 콘솔·게임 코드·저장·원문 정책 변경이 없으므로 외부 서비스 되돌림은 필요 없다. 기록만 취소하려면 이 문서 커밋을 되돌릴 수 있다. 이후 출시본 문제가 생기면 트랙 배포를 중단하고 더 높은 버전 번호의 수정 AAB를 제출하는 방식을 준비한다. 낮은 버전으로 단순 덮어쓰기나 사용자 저장 삭제로 해결하지 않는다.

문서 커밋·푸시 결과와 최종 원격 차이/작업 폴더 상태는 이번 작업의 최종 보고에 적는다. 그 결과를 확인하기 전 푸시 완료로 기록하지 않는다.
