# Play 결제 도입 준비 확인 · 2026-10-14

## 직접 확인
- 서버 브랜치 e275de9는 보존. origin/feat/ui-first-release 최신 ab70cc8(0.76.15)을 별도 budae-kiugi-ui 작업 폴더로 가져왔다. main/서버 병합 없음. UI에는 시설 상세보기 분리, 진급 진행률, 홈 메뉴/아이콘, 제목/건물 배치 개선이 포함된다.
- Play Console 부대 키우기: 일회성 제품 없음, 결제 권한을 APK에 추가해야 한다는 안내. 현재 코드에는 Google Play Billing 라이브러리/실제 구매/복원 미구현, 무료 개발 테스트 지급만 존재.
- 개발자 결제 프로필 화면 존재. 지급받을 방법에서 결제 수단 추가 필요 안내. 사업자 등록의 법적 유효성/모든 신원·세금 심사 완료는 확인하지 않았다. 계정/프로필 식별자·주소·금융정보는 기록하지 않음.
- 프로덕션 액세스 미승인. 화면상 비공개 테스트 참여12명/4일, 기준14일 안내. 결제 개발/비공개 시험과 정식 판매 가능 시점을 구분한다.
- 콘솔은 읽기만. 상품/가격/결제 수단/계약/정책/업로드 변경 없음. 종료된 서버는 재개하지 않았다.

## 판단 및 제안
- 앱 내 결제 구현 가능. 사업자 정보 등록만으로 기존 앱에서 결제가 시작되지는 않는다. Billing SDK/권한 → 결제 지원 테스트 빌드 → Play 상품 등록 → 구매/취소/보류/승인/재설치 복원/환불 후 권한 회수 검증 → 정책 확정 순서가 필요하다.
- 첫 대상으로 자동터치 영구 해금 같은 비소모성 일회성 상품 권장. 금액과 상품 구성은 사용자 결정 전 확정하지 않는다. 기존 무료 테스터 보유를 실제 구매 영수증으로 처리하지 않는다.
- 별도 게임 로그인/기존 Firebase 서버를 켜지 않고도 Play 계정 기반 구매 조회·앱 내 승인 구현은 가능하다. 다만 단말 검증만으로 조작 방지를 보장할 수 없고 Google은 안전한 백엔드 검증을 권장한다. 서버 미사용 결정과 검증 강도 선택은 구현 전에 설명한다. 서버 재개나 새 유료 서비스 도입으로 임의 대체하지 않는다.
- 구매 복원은 상품 이용권 복원이며 골드/병력/진행 저장 복원과 다르다. 소모성 재화와 일회성 스타터 보상은 중복 지급·유실 방지 설계가 더 필요하므로 먼저 영구 해금1종을 검증하는 안이다.
- 구매 보류에는 지급하지 않고 구매 완료 확인 후 지급/승인, 중복 콜백과 취소/환불/네트워크 중단 검증 필요. 정책번호11/약관8은 최종 승인 전 변경하지 않는다. 광고 테스트 ID 유지.
