# 상점 구매 경험 검토 · 2026-10-19 · 0.76.39

## 적용한 방향

사용자 요청은 기존 상품을 매력적으로 보여 주는 것이다. 새 상품·가격·수량·성능·지급 조건을 만들지 않았다. 홈 상점 버튼은 따뜻한 금색으로 구별하고, 상점 첫 상품인 스타터팩은 금색, 자동터치는 청록색으로 나눈다. 장식은 열릴 때 짧게 한 번만 움직이고 동작 줄이기 설정에서는 멈춘다.

스타터팩은 부스터 세 종류의 수량·배율·한 개의 지속시간을 함께 표시한다. 총70개이며 자동터치 미포함을 구매 버튼 위에 쓴다. 자동터치는 커서 그림, 초당10회, 영구 해금, 홈 전용, 중단되는 상황을 카드 본문에 보여 준다. 실제 결제 가격은 기존 Google Play 응답만 사용한다. 가격이 없으면 구매할 수 없다. 웹 개발 화면은 무료 테스트 문구와 확인 절차를 유지한다.

## 참고한 원칙과 한계

- [Nielsen Norman Group의 상품 페이지 연구](https://www.nngroup.com/articles/ecommerce-product-pages/): 그림·이름·가격·짧고 구체적인 설명·구매 가능 상태를 쉽게 찾게 한다. 이 원칙을 구성/효과/기간/구매 버튼의 배치에 적용했다. 판매 성과가 실제로 개선됐다는 검증은 아니다.
- [Google Play 결제 통합 문서](https://developer.android.com/google/play/billing/integrate): 상품 조회와 구매 확인의 실제 상태를 존중한다. 이번 변경에서 결제 처리·승인 대기·복원·취소·지급 로직은 수정하지 않았다. 현재 콘솔 설정과 실결제는 확인하지 않았다.
- Apple의 구매 UI 문서를 검색했으나 본문이 JavaScript/Markdown 제공 방식으로 완전히 열리지 않았다. 세부 구현의 검증 근거로 사용하지 않는다.

외부 디자인·그림을 복제하지 않았다. 기존 자체 SVG, 기존 라이선스가 보관된 글꼴만 사용했다. 근거 없는 할인율, 종료 시각, 인기 순위, 구매자 수, 계정당 중복 지급 방지, 다른 폰의 게임 진행 복원을 주장하지 않는다. 상품 구매는 플레이 진행의 필수 조건으로 표현하지 않는다.

## 확인 기준

- 320/390px에서 카드·가격·수량·시간이 잘리지 않는가.
- 홈 첫 줄은 전리품 상점 왼쪽, 전투 오른쪽이며 나머지 여섯 버튼은 그대로인가.
- 스타터팩은 받은 상태에서 다시 살 수 없고, 자동터치는 보유 후 켜기/끄기로 바뀌는가.
- 가격 조회 실패, 결제 처리 중, 저장 기록 비활성, 부스터 한도에서 기존 차단이 유지되는가.
- 상점 장식이 게임 수입·터치·저장·전투 성능을 바꾸지 않는가.

재현: 별도4233 주소의 `tools/store-gallery.html`은 모의 가격/보유/미수신 화면만 보여 준다. 결제나 게임 저장 접근은 없다. `tools/loot-qa.html`은 별도4233 시험 기록에서 실제 홈·상점을 검사한다. 4213의 사용자 기록을 시험 데이터로 바꾸지 않는다.
