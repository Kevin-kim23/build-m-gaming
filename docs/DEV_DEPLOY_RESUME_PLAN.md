# 개발 프로젝트 첫 함수 보존 재개 계획 · 0.83.19

2026-10-13. A안 준비·합성 검증 범위. 실제 재배포와 IAM 변경은 아직 실행하지 않았다. 이 계획의 남은 요청을 보고 최종 승인한 뒤 사람이 재개 전용 확인 문구를 입력한다. 운영 프로젝트는 대상이 아니다.

## 직접 확인과 한계

- 직접 확인: 가짜 자료에서 기존 첫 함수 검증, 기존 생성 생략, 새 함수8개/예약2개 흐름 및 거부 사례. 외부 전송0.
- 이전 직접 확인 기록: 기존 첫 함수의 콘솔 이름/서울/Node22/리비전 제한 일치, 인증 필요, 정상 상태, 예약0. 이번 작업에서 클라우드를 재조회한 것은 아니다.
- 미확인: 과거 실제 operation 응답의 실패 필드, 원격 실행 소스의 바이트 동일성, 실제 재개 성공 및 앱 로그인/저장. response.url은 합성 재현 후보이며 실제 원인 확정이라고 쓰지 않는다.

## 요청 도출과 검사

새로운 배포 요청 본문을 추측해서 만들지 않는다. 기존 capture-deploy-offline.cjs가 설치 firebase-tools15.33.0의 실제 요청을 외부전송 없이 도출한 deployment-template.json(33요청)을 다시 비교한다. 근거는 기존 오프라인 도출 문서 및 설치 CLI의 lib/gcp/cloudfunctionsv2.js, lib/deploy/functions/release/fabricator.js이다. 재개는 이 목록에서 첫 함수 생성과 그 operation 확인 두 항목만 빼고, 이미 inventory 모드에 허용된 목록 GET 한 건을 맨 앞에 둔다. 실제 비공개 값은 메모리에서만 결합한다.

기존 목록 경로: GET cloudfunctions.googleapis.com /v2/projects/{승인된 개발 프로젝트}/locations/-/functions, 쿼리 filter는 environment="GEN_2" 한 개만. 새 읽기 경로 확대 없음. 정확히 기존 첫 함수1개이며 누락/추가/다음 페이지/미응답 지역이 없어야 진행한다. 지역/프로젝트/Node22/실행 계정/인스턴스/진입 함수/활성 상태/환경 변수/라벨/메모리/동시 처리/시간 제한을 값 단위로 검사한다. 원문은 출력하지 않는다.

응답 검사는 정확한 해당 함수의 cloudfunctions.net 경로와 기존 run.app 루트 형식을 구분한다. 서비스 리소스의 프로젝트 표기는 지정 프로젝트 ID 또는 입력된 동일 프로젝트 번호만 허용한다. 다른 계정/지역/함수/프로젝트는 거부한다. 오류는 response.url 등 고정 필드 이름만 보여준다.

로컬 server/src는 최초 부분 배포 커밋3a7ac58과 차이가 없어야 한다. 이는 로컬 소스 연속성 검사이며 원격 파일 해시 증명이 아니다. 원격 소스 동일성을 완료 조건으로 요구했던 이전 비교안의 해당 부분은 미완료이며, 최종 승인 전에 이 한계를 알린다. 기존 함수 코드는 갱신하지 않는다.

| 나머지 함수 생성 | 8 | 원래9개 중 첫 함수 제외. 기존 함수 갱신/삭제 없음 |

| 예약 존재 확인/생성 | 4 | 지정된2개 각각 없음 확인 후 생성 |

일반 함수 전체6개 공개, 관리자 비공개, 예약2개 내부 수신을 유지한다. Node22/서울/인스턴스 제한/실행 계정/예약 일정은 원본 템플릿과 동일하다. 예약 주기는 삭제 재시도6시간마다, 만료 정리매일03시(KST)다. 서비스 계정 이메일/숫자 식별자/서명 주소/토큰은 문서에 저장하지 않는다.

기존 첫 함수의 현재 IAM 전체 정책은 이번에 조회하지 않았다. 기존 콘솔 인증 필요 관찰만으로 사용자 정의 추가 바인딩이 없다고 보증할 수 없다. 예정 setIamPolicy는 정책을 설정하는 변경이므로 최종 실행 전 콘솔에서 예상 밖 호출자 권한이 없는지 확인하거나 별도 좁은 읽기를 승인받아야 한다. 새 읽기 허용을 임의 추가하지 않는다.

## 실행과 중단

실행 진입점은 --resume-first와 별도 확인 문구 RESUME DEV PRESERVE FIRST FUNCTION ONCE를 요구한다. 이전 새 배포 명령과 확인 문구는 재개를 시작하지 못한다. 아직 실행 명령을 안내하거나 실행하지 않는다.

예상 밖 기존 함수, 설정 불일치, 허용되지 않은 요청, HTTP/통신/응답 검사 오류이면 첫 오류에서 멈춘다. 삭제/수정/자동 재시도/자동 API 활성화/전체 IAM 변경/정리 정책 변경은 추가하지 않는다. 함수 생성 요청 자체가 실패한 경우에도 이미 접수되었을 가능성은 별도 표시한다. 보존된 함수 수와 이번에 완료 응답까지 검증한 신규 함수 수를 구분한다.

이번 재개기는 정확히 첫 함수1개만 있는 상태 전용이다. 추가 함수가 생긴 뒤 중단하면 같은 명령을 무작정 다시 실행하지 않는다. 추가 작업 중단 → 생성된 종류/개수와 불확정 구분 → 예약이 있으면 사용자가 콘솔에서 일시정지 → 로컬 코드 복구. 서버 삭제/재배포는 별도 승인한다. git 복구만으로 클라우드 자원이 되돌아가지 않는다.

은행 비유: 이미 개설된 계좌를 다시 만들지 않고 전표를 대조한 뒤 남은 창구 업무만 이어간다. operation은 서버 작업 진행표, IAM은 호출 권한표다. 지금 사용자 행동 하나는 검사 결과와 남은 접근 권한 변경을 포함한 계획 검토다.

회사 PC 원본 보호 도구와 동일 보증 없음. 회사 PC에서 후속 비교 원칙 유지. 방침11·약관8 유지. 정책 영향 없음.
