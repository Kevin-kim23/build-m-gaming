# 자동터치 · 0.69.0

- 상점 → 아이템 → 자동터치. 4,900원은 예정 가격 표시이며 현재 실제 결제는 없습니다. ‘유료결제 테스트! 특별히 이번엔 그냥 드릴게요.’ 안내를 확인한 경우에만 영구 보유/켜짐으로 지급합니다. 취소·뒤로가기·중복 요청은 지급하지 않습니다.
- 같은 기기 저장에서 보유와 켜기/끄기를 유지합니다. 지금은 계정 연결이나 기기 간 구매 복원이 없으며, 앱 데이터 삭제 시 로컬 보유 기록도 사라집니다.
- 시작 화면을 마친 활성 홈에서 500ms마다 현재 터치 골드 1회분. 상점·장비·전투·설정·진급·상세·복귀 보상 등 모든 팝업과 교관 안내, 백그라운드, 다른 탭이 저장 잠금을 가진 동안에는 멈춥니다. 닫았다 열어도 쉬었던 시간은 보상하지 않습니다. 1초 넘게 타이머가 멈춘 구간도 따라잡지 않습니다.
- 직접 입력 이벤트를 만들지 않고, 손가락 슬롯/직접 터치 통계/스크롤을 수정하지 않습니다. 기존 10개 동시 손가락 입력은 그대로 작동합니다. 장군 리볼버의 기간제 자동 터치와 별개로 합산합니다.
- 현재 터치 수입을 공통 `perTap`으로 계산하므로 빨간물약·장군검·시설·개인 장비 효과가 동일하게 적용됩니다. 파랑물약은 초당 수입만 증가시킵니다. 골드는 공통 정확 정수 연산/1,000경 상한을 사용합니다.
- 기존 100ms 시계를 재사용하고 저장은 기존 2초 지연 저장을 사용합니다. 자동 골드 표시는 DOM 하나/투명도 애니메이션 하나를 재사용하며 효과음·진동·초점 이동·레이아웃 측정을 추가하지 않습니다.
- 저장 형식33 `homeAutoTap: {owned, enabled, source}`. 이전 저장은 미보유로 이관하고 나머지 진행을 유지합니다. 테스트 지급은 `source: 'test'`로 표시합니다. 이 값은 실제 결제 영수증이나 검증된 구매권이 아닙니다.
- `home-auto-tap-rules.js`는 저장 기본값·검증·보유 규칙만, `home-auto-tap.js`는 지급과 실행, `home-auto-tap-ui.js`는 카드·구매 요청·표시, `test-purchase.js`는 테스트 팝업을 담당합니다. 저장 정의는 게임 계산 모듈을 역으로 불러오지 않습니다.

## 과금·권리 확인 (2026-10-08)

- 실제 청구·Google Play 결제 SDK·외부 통신·새 권한·개인정보 수집을 추가하지 않았습니다. 버튼과 팝업 모두 테스트/미청구를 명시합니다. 새 아이콘은 직접 작성한 SVG, 모집 계급장은 기존 자체 제작 그림 재사용입니다.
- 출시 판매 전에 테스트 지급 경로를 실제 Google Play 결제로 교체하고 구매 검증/확인 처리, 복원, 취소·환불 시 보유 처리 및 기존 무료 테스트 보유자의 처리 방침을 확정해야 합니다. 클라이언트 `source`만으로 실제 구매를 인정하면 안 됩니다.
- 공식 근거: [Google Play 구매 검증 권고](https://developer.android.com/google/play/billing/security), [Google Play 결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738). 현재 테스트 구현을 정식 결제 완료로 간주하지 않습니다.
