## 시간순 작업

1. 사용자 결정과 저장소 규칙을 읽고 로컬·원격 브랜치 및 변경 상태를 확인했다.
2. Codex의 관리 작업 폴더 생성 기능은 현재 채팅 경로가 Git 저장소가 아니어서 실패했다. 실제 중첩 저장소 위치를 확인한 뒤 Git의 별도 작업 폴더 기능으로 정상 생성했다.
3. main 80261e1에서 feat/ui-first-release를 만들었다. 이전 서버/UI 브랜치를 수정하거나 합치지 않았다.
4. 기존 서버 기반 미리보기의 로컬 프로세스만 확인해 종료했다. 브라우저 기록과 클라우드는 변경하지 않았다.
5. 새 폴더에 의존성을 설치하고 main/서버의 방침·약관·스토어 자료를 읽어 목록을 작성했다. 읽기 명령의 파일 필터에 배열을 넣어 발생한 조회 오류는 단일 필터로 다시 확인했다. 원문 변경은 없었다.
6. AGENTS.md, CONTINUE.md, 검증결과.md에 첫 출시 범위와 이어서 작업할 위치를 기록했다. 서버 관련 문구 목록은 별도 보고서에만 작성했다.
7. npm test 721개 통과, npm run build 성공. 빌드의 기존 큰 청크 및 시간 측정 경고를 확인했다. 기능·의존성·정책 버전 변경은 없다.
8. 새 브랜치의 문서 변경만 커밋·푸시 대상으로 삼았다. 최종 원격 동기화와 작업 폴더 청결 여부는 완료 보고에서 확정한다.
9. 커밋 전 공백 검사에서 새 목록 문서의 마지막 빈 줄 1개가 발견되어 커밋을 보류했다. 빈 줄을 제거한 뒤 검사를 다시 실행했다. 문서 변경 후 버전 동기화 검사 5개도 통과했다.

## 확인 수준과 범위

- 사용자 결정: 첫 출시에서 로그인·닉네임·클라우드 저장·랭킹 제외. 서버 작업 중단, 서버 브랜치 삭제·main 통합 금지.
- 직접 확인함: 최신 원격 main(`origin/main`) `80261e1`(0.76.1)에서 독립 `feat/ui-first-release` 생성. 기존 로컬 main(`e72aecb`)은 전환·이동하지 않았다. 서버 브랜치 `feat/firebase-server-test`(`89ad29d`)와 이전 UI 브랜치 `feat/ui-improvements`(`cfa74ab`) 보존.
- 별도 작업 폴더는 기존 저장소와 나란한 `budae-kiugi-ui`. 회사 PC의 절대 경로는 집 PC에서 달라질 수 있다. 이후 명령은 반드시 새 폴더에서 실행한다.
- 직접 확인함: 새 브랜치에는 추적된 `server/`, `cost-control/`, 배포 보호 도구, Firebase 의존성이 없다. 게임 실행 코드·Android·패키지 파일은 main과 동일하다.
- 직접 확인함: npm ci 완료, `npm test` **721/721 통과**, `npm run build` 성공. 기존 큰 청크 경고와 플러그인 시간 측정 경고가 있으며 빌드 실패는 아니다.
- 방침·약관·스토어 원문 및 번호는 수정하지 않았다. main의 방침7·약관4, 보관 서버 브랜치의 방침11·약관8 모두 그대로다. 기능 변경이 없어 앱 버전 0.76.1 유지.
- 목록은 [첫 출시 서버 문구 목록](FIRST_RELEASE_SERVER_TEXT_INVENTORY.md)에 기록했다. 서버 스냅샷과 main 내용을 구분하고 광고 서비스의 Google 서버 처리도 별도로 분류했다.
- 기존 서버 기반 로컬 UI 미리보기(4196)는 혼동 방지를 위해 종료했다. 새 미리보기는 아직 실행하지 않았다. 브라우저 게임 기록은 변경하지 않았다.
- 미확인: 실제 공개 방침·스토어 게시본, 현재 클라우드 함수·예약·과금 상태, 실폰 동작. 클라우드·인증·배포에 접근하지 않았다. 이미 배포된 서버는 이 작업으로 중단되지 않는다.
- 푸시 대상은 새 UI 브랜치뿐이다. 커밋·푸시 성공 및 원격 차이 0/0 여부는 작업 종료 시 Git으로 확인해 최종 보고한다. main·기존 두 브랜치에는 쓰지 않는다.

## 비유·다음 단계·주의

- 은행 비유: 별도 보관한 서버 설계도를 합치지 않고, 출시용 게임 설계도에서 UI 작업실을 새로 만들었다.
- 브랜치: 변경 기록을 나누는 이름. 작업 폴더: 각 기록을 실제 파일로 열어 두는 공간.

## 0.76.2 홈 UI·일괄 모집 변경 (시간 순서)

1. 새 UI 작업 폴더와 규칙을 읽고 서버 미포함 범위를 확인했다. 설문으로 준위 일괄 모집 시점, 미보유 아이템 안내, 2×3 메뉴를 확정했다.
2. 변경할 모집/진급 규칙을 재현하는 테스트 4개를 먼저 작성했다. 기존 코드에서 실패함을 확인한 뒤 수정했다.
3. 규칙 공통 정의와 홈 아이템 표시 모듈을 수정했다. 기존 물약·자동터치·스킬 처리 함수를 재사용하고 별도 저장/타이머를 추가하지 않았다. 관련 가이드 이동과 팝업 포커스 복귀도 함께 맞췄다.
4. 첫 전체 검사에서 이전 진급 인원 제한을 가정한 테스트, 신규 글자 크기, 과거 학교 보상 호환성 문제가 드러났다. 새 규칙의 기대값을 맞추고 과거 저장 보상은 별도 유지했다. 이후 전체 검사를 다시 실행했다.
5. 아래 검증을 마쳤다. 화면 검증 도중의 테스트 초기화 플래그는 시나리오별로 분리하여 신규/보유 화면이 섞이지 않도록 고쳤다.
- 직접 확인함: 지휘봉 Lv.1은 일반병·행정병·운전병·의무병 100명 모집, Lv.5는 원사와 준위 100명 모집을 함께 연다. 나머지 해금 레벨 유지.
- 직접 확인함: 모든 진급의 특정 병종 보유 인원 조건을 제거하고 전력 조건만 유지. 모집의 학교/계급 조건은 유지한다. 형식9 이전 저장의 학교 보상은 당시 규칙을 별도로 보존한다.
- 직접 확인함: 홈 우측 상단에 빨강/파랑 물약·자동터치 블록, 보유한 장군검·리볼버 사용 블록. 미보유 물약은 기존 광고 획득 화면, 자동터치는 기존 구매 안내 화면으로 연결한다. 광고/결제 자체 구현은 변경하지 않았다.
- 직접 확인함: 하단 군대 모집·시설·장비·개인장비·상점·아이템을 2행×3열로 배치. 전투 진입은 별도로 유지. 홈 훈장은 숨기고 설정의 도전과제·훈장 화면에서 확인한다. 기존 훈장 기록 보존.
- 직접 확인함: 회귀 테스트 4개로 기존 결함을 재현한 뒤 구현. 집중 검사 37개/92개 통과, 전체 npm test 729/729 통과, npm run build 성공. 기존 라이선스 청크 크기 경고만 남는다.
- 직접 확인함: 실제 게임과 분리된 4207 테스트 화면에서 320×640 및 412×915 배치 확인. 320px의 메뉴 터치 높이 44px 이상, 가로 넘침 없음. 물약/스킬 활성·대기시간, 자동터치 전환, 6개 메뉴, 미보유 광고/구매 안내와 팝업 종료 후 포커스 복귀 확인.
- 직접 확인함: 테스트 기록은 별도 포트에서만 생성했다. 실제 4196 저장을 테스트 데이터로 덮어쓰지 않았다. 저장 키/형식 변경 없음.
- 미확인: Android 실폰, APK/AAB 재빌드, 실제 광고 시청/결제. 이 PC에 Git 제외 배경음 4곡이 없어 music.media 오류가 발생한다. 음원 파일·권리·재생 설정은 변경하지 않았다.
