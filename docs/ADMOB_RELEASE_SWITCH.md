# 물약 광고·자동터치 출시 연결 기록 · 0.76.3

## 지금 직접 코드에서 확인한 것

- 물약 독립 팝업 → `createPotionController.watch` → `createPotionAd` → Android `PotionAdsPlugin.showRewarded`로 연결된다. 상점의 기존 광고 버튼도 같은 컨트롤러를 사용한다.
- `android/app/build.gradle`의 `defaultConfig`, `debug`, `release` 모두 Google 공식 샘플 앱/보상형 광고 ID다. 이번에는 변경하지 않았다. 사용자 실제 AdMob 광고 단위가 연결됐다고 표현하지 않는다.
- `PotionAdsPlugin.java`는 `potion_rewarded_ad_unit` 리소스로 광고를 요청한다. 보상 콜백이 발생하면 earned 상태를 기록하고, 닫힐 때 그 상태가 참인 경우에만 rewarded를 반환한다. 단순 광고 닫기/실패는 물약을 지급하지 않는다.
- 기존 앱의 광고 동의·연령 처리·Google 동의 화면·오디오 일시 중단 흐름을 그대로 재사용한다. 광고 요청을 서버 로그인과 혼동하지 않는다.
- 웹에서는 Android 전용 광고가 unavailable이다. 미지원 안내가 표시되고 물약이 지급되지 않는 것을 브라우저에서 확인했다.
- Android 실폰 광고 재생, AdMob 계정 승인 상태, 실광고 수익 보고는 이번에 확인하지 않았다. APK/AAB도 만들지 않았다.

## 승인 후 실광고 전환할 곳 (아직 실행하지 않음)

1. 사용자가 AdMob 콘솔에서 앱 준비 상태, 광고 단위, 개인정보/연령/동의 설정을 확인한다. 단순히 승인 메일 하나만 보고 자동 전환하지 않는다.
2. `android/app/build.gradle`의 **release** `admob_app_id`와 `potion_rewarded_ad_unit`을 승인받은 실제 앱/보상형 광고 단위 값으로 변경한다. debug는 Google 테스트 ID를 유지한다. defaultConfig 값과 release 덮어쓰기 관계도 같이 검토한다.
3. 같은 보상형 리소스를 쓰는 터치 부스터·초당 부스터·오프라인 보상 모두 확인한다. 별도 광고 단위를 쓰기로 바뀌면 항목별 매핑과 테스트를 먼저 추가한다.
4. 현재 `tests/`의 샘플 ID 고정 검사를 찾아 debug 테스트 유지와 release 실제 값 검증으로 의도적으로 갱신한다. 샘플 ID가 출시 빌드에 남거나 실제 ID가 개발 테스트 빌드에 섞이지 않도록 검사한다.
5. 기존 정책 원문, 앱 내 동의 화면, Play 데이터 보안/광고 포함 여부를 실제 배포 설정과 대조한다. 이 문서 자체는 정책 게시나 개정 번호 변경이 아니다.
6. 실폰은 테스트 기기로 등록하여 보상 완료·취소·통신 실패·중복 누름·앱 백그라운드 복귀·오디오 복구를 검사한다. 자기 실광고를 클릭하며 시험하지 않는다.
7. Android 리소스 변경은 웹 새로고침만으로 반영되지 않는다. 웹 빌드·Android 동기화·서명 APK/AAB 재빌드 및 설치로 검증한다. 사용자 승인 후 업로드한다.

실제 계정 값·토큰·서명 정보는 이 문서에 기록하지 않는다. 이번 UI 브랜치에서는 Firebase 서버 작업을 하지 않는다.

## 자동터치 구매

- 독립 팝업은 예정 가격 4,900원과 효과를 설명한다. 개발에서는 기존 명시적 무료 테스트 확인 팝업으로 연결한다.
- 출시 빌드의 신규 실제 결제/복원은 아직 연결되지 않아 구매 버튼이 비활성이다. 이전 테스트 보유 기록을 유료 결제 영수증으로 간주하지 않는다.
- Google Play Billing과 상품 등록·구매 검증·복원은 별도 구현 과제다. 이 UI 변경을 실제 결제 완료로 보고하지 않는다.
