# 방치 수익과 수동 터치 피드백 · 0.76.27

확인 날짜: 2026-10-17. 기준 브랜치: `feat/ui-first-release`.

방치 수익에서 선택과 지급액을 빨리 읽고, 수동 터치가 골드 획득으로 이어졌음을 바로 알 수 있도록 화면을 개선했다. 지급 규칙·저장 데이터·광고 보상 판정은 변경하지 않았다.

## 방치 수익 화면

- 먹청색 바탕·아이보리 글자·황동색 강조를 기존 홈·상점과 맞췄다.
- 제목은 ‘방치 수익’으로 줄였다. 정산 시간·최대 8시간·받을 골드·광고 보상·일반 받기만 기본 화면에 표시한다. 오류와 보유 한도 안내는 필요한 경우에만 나온다.
- 기존 홈 동전 그림을 재사용한다. 외부 그림·폰트·라이브러리를 추가하지 않았다.
- 중앙 금액을 가장 크게 표시하고, 광고 선택에는 ‘광고 보고 2배 받기’와 시청 완료 후 총 지급액을 함께 표시한다. ‘그냥 받기’는 별도 48px 이상 버튼으로 유지한다. 닫기 버튼도 44px이며 보상을 보관하는 기존 동작을 유지한다.
- 동전 등장 420ms와 광고 버튼 광채 1,100ms는 한 번만 재생한다. 계속 점멸하거나 버튼 위치를 움직이지 않는다. `prefers-reduced-motion: reduce`에서는 장식 움직임을 끈다.
- 광고 확인 중에는 중복 선택을 막고 상태를 표시한다. 취소·실패 때에는 보상을 보관하며 일반 받기를 다시 이용할 수 있다. 실제 보상 완료 여부는 기존 광고 어댑터와 컨트롤러가 판정한다.

### 보유 한도와 광고 표시

표시 금액은 `money.js`의 정확한 금액 연산으로 계산한다. ‘원래 방치 보상’과 ‘현재 보유 한도에서 실제 지급 가능한 금액’을 구분한다.

| 상황 | 표시와 선택 |
| --- | --- |
| 한도 여유가 충분함 | 일반 지급액과 광고 시 총 2배 지급액을 표시 |
| 광고 총액만 한도에 걸림 | 실제 가능한 총액을 표시하고 ‘광고 보고 추가 받기’로 변경. 2배라고 약속하지 않음 |
| 광고로 추가 지급되는 골드가 0 | 광고 버튼을 숨김. 일반 받기는 유지 |
| 이미 보유 한도에 도달함 | 실제 받을 수 있는 0 G와 한도 안내를 표시. 일반 받기로 보상을 정산 |

큰 금액의 화면 축약은 기존 `fmtGold`를 사용하며, 지갑·정산 값 자체를 반올림하거나 `Number`로 변환하지 않는다. 광고 버튼의 총액 설명도 보유 한도를 반영한다. 화면 표시와 실제 `claimOfflineReward` 결과가 안전 정수 경계·큰 금액·상한 직전 1 G에서 일치하는지 비교 테스트를 추가했다.

## 수동 터치 피드백

- 수동 터치 때 상단 골드 숫자가 최대 1.12배로 커졌다가 260ms 안에 제자리로 돌아온다. 실제 글꼴 크기나 배치 폭은 바꾸지 않는다.
- 확대 기준점을 중앙으로 두고 동전·단위와 간격을 확보했다. 긴 계급명은 좁은 화면에서 두 줄로 보여 골드 영역과 겹치지 않는다.
- 황동빛 강조와 터치 위치의 짧은 원형 효과로 입력 위치와 획득 결과를 연결한다. 화면 전체 흔들림은 추가하지 않았다.
- 연속 터치 시 상단 애니메이션은 이전 것을 취소하고 하나로 대체한다. 떠오르는 골드 숫자는 최대 15개, 터치 원형 효과는 최대 6개로 제한하고 수명 종료 후 제거한다.
- 동작 줄이기를 켜면 확대·이동·원형 효과를 생략하고 고정 위치 숫자와 짧은 고정색 강조만 사용한다.
- 이 효과는 수동 터치 경로에만 적용한다. 자동터치 10회/초나 초당 자동 수입이 상단 확대 효과를 계속 발생시키지 않는다. 자동터치의 속도·지급량도 변경하지 않았다.

## 검증

### 완료한 범위

- 방치 수익 UI·기존 정산·네이티브 광고 어댑터·큰 금액 관련 테스트 **40/40 통과**.
- 일반 받기, 중복 선택, 닫은 보상 재표시, 광고 대기·취소·실패, 완료 후 정확한 2배 지급, 보유 상한 분기 확인.
- 해당 변경을 포함한 웹 빌드 성공. 기존 `runtime-notices` 청크 크기 경고 유지.
- 통합 담당이 Chrome 390px 폭에서 방치 수익 팝업 표시를 확인했다. 이는 웹 화면 확인이며 실기기 확인과 구분한다.

### 최종 통합 결과

- 전체 `npm test`: **831/831 통과**, 실패0·건너뜀0,172.98초. 이후 긴 계급명과 골드 여백 CSS만 조정하고 관련21/21을 재검사했다. 마지막 CSS 뒤 전체 재실행은 하지 않았다.
- 최종 `npm run build`: **성공**,489ms. 기존 runtime-notices885.32kB 청크 경고 유지.
- Chrome390×844/320×640: 가로 넘침 없음, 닫기44px·일반48px·광고76px. 390×520에서도 모든 버튼이 팝업 안에 표시됨.
- 320px 긴 계급명·큰 골드: 확대된 숫자 양쪽에 동전/단위와3.35px 여유, 긴 계급 두 줄 표시. 390px 일반 숫자 양쪽3.89px 여유. 폰트 크기가 반복 변경되지 않음.
- 가짜 광고 완료 후720,000 G, 취소 후 일반360,000 G 지급 확인. 실패 후 보상 보관, 한도 근처 총150 G의 추가 받기, 상한 도달 광고 숨김 확인.
- 가짜10회 연타 후12,500 G 증가, 잔여 숫자/원형 효과0개. 브라우저 로그 오류·경고0.80회 연타 상한/애니메이션 대체/동작 줄이기는 단위 테스트에서 검증했다. 실제 Android의 동작 줄이기 설정 연동은 미확인이다.
- 캡처는 모두 가짜 기록: [방치 수익](ui/0.76.27/offline-390.png), [골드 확대 순간](ui/0.76.27/tap-hud-390.png). 확대 순간은 QA 버튼으로 애니메이션 첫 프레임을 일시정지해 촬영했다. 실제 게임은260ms 안에 복귀한다.
- Git: UI 브랜치에만 커밋·푸시 예정. 결과는 작업일지에 기록.

### 미확인

- 실제 Android 기기에서의 반응 속도·연타 성능·동작 줄이기 설정 연동.
- 실제 광고 로드·시청·보상 지급. 자동 테스트는 가짜 광고 응답을 사용했다.
- 사용자 조사와 광고 선택률·피로도·재방문율 비교.
- 새 AAB 생성·Play 업로드는 이번 UI 검증 결과만으로 완료라고 표시하지 않는다.

## 유지 범위와 되돌림

저장 키 `budae-kiugi-recruits-v3`, 저장 형식 42와 이전 형식 migration, 보상 1시간 기준·최대 8시간·2배 지급 규칙, 큰 금액 처리, 광고 테스트 ID, SDK·권한·외부 통신, 방침 12·약관 9를 유지한다. 실제 사용자 저장은 검증 자료로 덮어쓰지 않는다. 서버·콘솔 설정을 변경하지 않는다.

되돌림은 이번 UI·표시·피드백 변경을 역커밋하고 테스트·빌드로 확인한다. 저장 구조가 바뀌지 않아 저장 데이터 변환이나 삭제가 필요하지 않다.

정책 영향 없음. 기존 출시 시 자동터치 상품 설명 10회/초 동기화 과제는 별도로 유지한다.
