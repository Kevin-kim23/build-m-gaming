## 1. 작업을 시작하기 전에 (공통)
- [ ] 쓸 서비스 하나를 정한다 (광고 회사, 결제는 Google Play 결제).
- [ ] 그 서비스의 공식 개인정보·SDK 안내를 읽고 "무엇을 수집하는지" 메모한다.
- [ ] 대상 연령을 정한다. 어린이 대상이면 광고·개인정보 규칙이 훨씬 엄격하다 (확인 필요).
- [ ] 이 작업은 **한 번에 하나만** 한다 (광고와 결제를 같은 버전에 섞지 않는다).

## 2. 광고를 넣을 때
코드
- [ ] 공식 SDK만 추가한다. 추가한 이름·버전·라이선스·출처를 README에 기록한다.
- [ ] `src/potion-ad.js` 및 네이티브 `PotionAdsPlugin` 경로에서 광고를 부르고, 보상은 **광고 시청 완료 콜백**에서만 지급한다 (닫기 버튼이 아니다).
- [ ] 광고가 없거나 실패해도 게임이 진행된다 (오프라인 보상은 일반 받기가 가능).
- [ ] 매 프레임·1초 타이머 안에서 광고·저장을 부르지 않는다.
- [ ] 테스트용 광고 ID와 실제 광고 ID를 분리한다. 실제 광고를 개발 중에 눌러 보지 않는다 (계정 정지 위험).

문서·설정
- [ ] `src/privacy-policy.js` "수집하는 개인정보"를 고친다: 어떤 SDK, 무슨 정보, 왜, 누가 처리, 국외 이전 여부, 거부·삭제 방법.
- [ ] `POLICY_DATE`, `POLICY_REVISION`을 올리고 `npm run privacy:doc` 실행.
- [ ] 테스트의 허용 목록(`tests/privacy-policy.test.js`)을 방침과 **함께** 고친다.
- [ ] Play Console 데이터 보안 양식: 광고 ID, 기기 ID 등 수집·공유 항목 체크 (확인 필요).
- [ ] AndroidManifest의 광고 ID 권한 선언 (확인 필요).
- [ ] 이용자 동의 화면: 필요한 지역과 방식을 광고 회사 안내로 확인 (확인 필요).
- [ ] Play 콘텐츠 등급 설문, 광고 포함 표시를 다시 작성한다.
- [ ] 방침 웹 주소의 글도 같은 내용으로 갱신한다.
- [ ] 광고를 붙인 버전은 새 버전 번호로 비공개 테스트부터 다시 한다.

## 3. 앱 내 결제를 넣을 때
코드
- [ ] Google Play 결제 라이브러리(공식)만 사용한다. 카드번호는 앱이 받지 않는다.
- [ ] 구매 기록(상품 ID·시각)을 저장한다면 저장 형식을 올리고 이전 저장을 읽는 테스트를 추가한다 (AGENTS 규칙).
- [ ] 구매 복원(재설치·기기 변경)을 지원한다.
- [ ] 결제 확인 방식을 정한다. 서버 검증을 쓰면 그 서버가 개인정보를 다루게 되어 방침에 적어야 한다 (확인 필요).
- [ ] 큰 금액(골드)과 결제 보상은 `money.js` 공통 함수로 처리한다.

게임 설계
- [ ] **확률형 아이템을 유료로 팔지 않는다.** 팔 경우 한국 게임산업법의 확률 공개 의무를 확인한다 (확인 필요). 현재 개인 장비는 확정 강화다. 향후 확률 요소를 도입하면 다시 검토한다.
- [ ] 결제 없이도 끝까지 갈 수 있는지(현재 부사령관까지)와 결제가 그 속도를 어떻게 바꾸는지 밸런스를 점검한다.

문서·설정
- [ ] 방침: 구매 기록 저장 여부, 결제는 Google이 처리한다는 사실을 적는다.
- [ ] Play Console: 상품 등록, 가격, 상품 설명, 데이터 보안 양식, 콘텐츠 등급 재작성.
- [ ] 한국 소비자 보호: 가격·상품 표시, 환불 안내, 청약철회, 미성년자 결제 안내 (확인 필요).
- [ ] 수익이 생기면 사업자 등록, 통신판매업 신고, 세금 (세무사·관할 기관 확인).
