## 한 단계씩 진행하는 안내

### 1. 폰 연결만 확인

사용자: USB로 폰을 연결하고 개발자 옵션의 USB 디버깅을 켠다. 이 PC를 확인한 뒤 폰의 디버깅 허용을 누른다. 채팅에는 ‘연결했어’만 알린다. 아직 앱 설치/로그인하지 않는다.

Codex: ADB는 기기 수와 연결 상태만 출력한다. 기기 일련번호/전체 devices 원문을 기록하지 않는다. unauthorized이면 폰 승인 화면을 사용자에게 안내하고, 여러 기기이면 사용자 선택 전 설치하지 않는다.

은행 비유: 시험 창구에 사용할 단말기만 연결하는 단계다. USB 디버깅은 PC가 개발 앱을 설치·점검하도록 허용하는 기능이다.

### 2. 개발 APK 하나 확정·검사

Codex: 선택한 APK의 패키지/버전/서명/내장 development 및 dev 프로젝트/Debug App Check 제공자/테스트 광고를 검사한다. 기존 파일을 쓰면 검증 전 최신이라고 부르지 않는다. 신규 빌드는 저장소의 `npm run android:apk`가 Debug 경로에서 음원 검사 → android:sync:firebase → assembleDebug를 실행한다. Node22·JDK21 환경에서 수행하며 원문 빌드 로그의 개인경로/서명 정보를 채팅에 내보내지 않는다. 결과는 성공/실패와 안전한 요약만 기록한다.

멈춤: 운영 프로젝트/패키지, 서명 충돌, 오염된 저장, 빌드 실패. 기존 앱 제거·데이터 지우기 금지. APK에 테스트 표식이 맞는지 확인한 뒤에만 폰 설치 단계로 간다.

### 3. 사용할 APK의 SHA-1 등록 확인

Codex: 실제 선택한 APK의 서명 인증서를 기준으로 지문을 로컬에서 비교한다. PC 이름이나 과거 키 기록만으로 등록 완료라 판단하지 않는다. 인증서 지문은 비밀번호가 아니지만 여기서는 값 대신 일치/미등록 결과만 보고한다.

사용자: Firebase 콘솔 → 개발 프로젝트 → 프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → Android .dev 앱 → SHA 인증서 지문으로 이동한다. 먼저 화면을 여는 동작만 안내하고 결과를 받는다. 사용할 APK의 SHA-1이 있으면 유지한다. 없으면 등록할 지문과 대상 앱을 확인하고 사용자가 직접 추가한다. 다른 PC 지문을 지우지 않는다. Google 로그인 제공자 활성화 여부도 읽기로 확인한다. OAuth 설정 변경으로 새 google-services.json이 필요하면 debug 전용 위치와 Git 노출 여부를 확인한 뒤 반영/재빌드하며 운영 설정을 덮어쓰지 않는다.

은행 비유: 이 APK를 만든 제작자의 도장을 등록하는 절차다. SHA-1은 APK 서명 인증서 지문이다.

### 4. 개발 앱 설치·깨끗한 시험 진행 확인

패키지 .dev가 기존 출시 앱과 별도임을 확인하고 설치한다. 이미 .dev 앱에 진행이 있으면 자동 초기화하지 않는다. 실제 사용자 기록/만렙 기록을 서버에 올리지 않도록 별도의 깨끗한 시험 환경을 먼저 정한다. 업데이트 서명 오류 시 앱을 지우지 말고 멈춘다.

사용자는 앱의 개발용 표시만 확인해 알려준다. 이메일이 나오는 계정 화면은 가리지 않은 캡처로 보내지 않는다.

### 5. App Check 디버그 토큰 등록 — 사용자 직접, dev만

코드 확인: Android debug는 DebugAppCheckProviderFactory, release/unsigned는 Play Integrity 제공자를 사용한다. 실제 빌드에 포함됐는지2단계에서 별도 확인한다.

사용자: Firebase 개발 프로젝트 → App Check → 앱 목록 → .dev Android 앱 → 점3개 → 디버그 토큰 관리 화면을 연다. 메뉴가 없거나 앱이 미등록이면 멈추고 상태만 알려준다. 운영 앱을 선택하거나 보호 검사를 끄지 않는다. 앱 등록 등 추가 설정이 필요하면 그 범위를 별도로 확인한다.

사용자만 로컬 Logcat의 DebugAppCheckProvider 출력을 보고 해당 폰에서 생성된 토큰을 복사한다. 토큰이 나오는 동작은 네이티브 App Check 토큰 요청이다. 현재 앱에서 로그인 후 서버 조회 때 처음 요청될 수 있으므로 토큰이 아직 없다고 오류로 단정하지 않는다. 필요하면6단계의 테스트 로그인만 먼저 하고 서버 조회 실패는 ‘등록 전 미완료’로 구분한다. 로그 전체 내보내기·파일 저장·채팅 붙여넣기 금지. Codex는 토큰을 대신 읽거나 출력하지 않는다.

사용자가 dev 앱의 디버그 토큰 관리에 직접 붙여넣고 저장한다. 채팅에는 ‘dev 등록했어’만 보낸다. 재시도 전에 등록 대상 앱을 확인하며 지연/오류 시 반복 호출하거나 App Check를 해제하지 않는다. 개발 토큰은 실제 기기 무결성 검사 대신 쓰는 시험 허가증이므로 공개하지 않는다. 이 성공은 Play 설치 앱의 Play Integrity 성공 증거가 아니다.

### 6. 테스트 전용 Google 계정 로그인

사용자: 실제 게임 기록·결제·관리자 권한이 없는 본인 소유 시험 계정을 준비한다. 이메일/비밀번호/OTP/복구 코드는 채팅에 보내지 않는다. 앱 설정의 ‘구글 계정 연결’ → ‘Google로 로그인’에서 직접 계정을 선택하고 인증한다. 화면에 로그인 완료가 보이면 결과만 알린다. 다른 계정이 선택되면 저장하지 말고 중단한다.

로그인은 성공했지만 서버 조회가 실패하면 Google Auth와 App Check/Functions 문제를 분리한다. API 권한/앱 검사를 풀어서 통과시키지 않는다. 수동 실패 재시도 전에 고정 오류 종류를 확인한다.

### 7. 닉네임 → 서버 저장

사용자: ‘닉네임 · 서버 기록’에서 시험용 닉네임을 등록한다. 실제 개인정보를 닉네임에 넣지 않는다. 신규 시험 진행의 작은 수치만 사용하고 만렙/실제 저장을 가져오지 않는다. 저장 버튼의 확인 화면을 읽고1회 저장한다. 완료 표시와 서버 기록 조회의 일치 여부를 확인한 뒤 다음 단계로 간다. 로그인만으로 저장 완료라고 쓰지 않는다.

### 8. 서버 불러오기

서버 저장이 확인된 뒤 시험 진행만 조금 바꾼다. 서버 불러오기 전 ‘이 기기의 복원 전 백업’이 생성되고 공간/10개 제한에 문제가 없는지 확인한다. 사용자가 확인한 뒤 불러오기1회. 서버에 저장했던 진행으로 돌아왔는지 확인한다. 기존 실제 저장과 혼합하지 않는다. 백업 공간 부족 시 자동 삭제/데이터 초기화 금지.

### 9. 테스트 게임 계정 삭제 — 나중에 별도 확인

현재 사용자는 삭제 금지를 지시했으므로 이 단계는 문서만 준비했다. 실제 시험할 때 대상이 시험 계정임을 재확인하고 사용자가 삭제 확인 화면에서 직접 실행한다. Google 계정 자체 삭제가 아닌 ‘서버 계정·기록 삭제’다. 최근 재로그인이 필요하면 사용자 직접 진행한다.

Codex는 승인된 방법으로 Auth·프로필·닉네임·저장 등의 제거 결과를 확인하고, 일부 실패/재시도 대기와 완료를 구분한다. 완료 확인 최소 기록90일 보관은 게임 저장 보존과 다르다. 기기 진행/복원 백업이 유지되는지도 확인한다. 성공 화면만으로 모든 관련 데이터 삭제를 완료라고 하지 않는다. 원문 문서/UID/이메일 출력 금지.

## 종료 기준과 되돌림

한 단계 실패 시 뒤 단계 보류. 서버 배포나 IAM 변경으로 자동 해결하지 않는다. APK 설치를 되돌릴 때에도 기존 앱 제거/데이터 삭제는 자동으로 하지 않는다. 계정 삭제는 복구 불가이므로 시험 계정 확인을 생략하지 않는다. 시험 종료 후 로그아웃·디버그 토큰 폐기 여부를 사용자와 정하고, 이번 준비에서 실행하지 않는다.

기록은 각 단계의 성공/실패/미확인, APK 버전과 dev 여부, 오류 종류만 남긴다. 실기기 로그인·저장 성공과 예약 자연 실행 성공은 각각 다른 체크 항목이다. 내일 자연 실행을 확인하기 전5단계 전체 PASS라고 쓰지 않으며, 오늘 실기기 준비·제한된 로그인 시험을 하더라도 그 미완료를 유지한다.
