## 2. 폰에서 먼저 실행

APK를 폰으로 옮겨 설치합니다. 같은 앱이 있으면 업데이트로 설치하며, 설치 오류가 난다고 기존 앱을 바로 삭제하지 마세요. 삭제하면 저장이 사라질 수 있습니다. 출처 허용 안내는 APK를 여는 앱에만 적용하고 설치 후 필요 없으면 해제하세요.

확인할 것: 로고 → 시작 화면 음악 → 터치해서 홈 진입 / 홈1→홈2→홈1 / 실제 전투 음악 / 설정에서 효과음과 배경음을 각각 0%와 중간값으로 조절 / 재시작 후 볼륨 유지 / 다른 앱으로 나갈 때 음악 중지 / 돌아올 때 음악과 진행 정상 / 지도 핀치·출격 드래그.

현재 자동 테스트·브라우저 검증과 서명 빌드는 했지만 실제 폰 청취·터치 검증은 대신하지 못했습니다.

## 3. 공개 개인정보처리방침 URL 준비

GitHub 저장소에는 앱과 같은 원본으로 생성한 docs/privacy/index.html이 있습니다.

GitHub의 Kevin-kim23/build-m-gaming → Settings → Pages → Deploy from a branch → main /docs → Save로 공개할 수 있습니다. 기존 Pages 설정이 있다면 바꾸기 전에 현재 호스팅 내용을 확인하세요.

처음 활성화했다면 배포가 성공한 뒤 예상 주소 https://kevin-kim23.github.io/build-m-gaming/privacy/ 를 로그아웃 상태에서 직접 열어 확인합니다. **이 주소는 Pages 활성화·배포 성공을 아직 확인한 주소가 아닙니다.** 정상 표시된 실제 주소를 콘솔에 입력하세요. 로그인 요구·PDF·로컬 경로는 사용하지 마세요. 앱 안에서는 설정 → 개인정보처리방침으로 볼 수 있습니다.

## 4. Play Console에서 앱 만들기

https://play.google.com/console 에 개발자 계정으로 로그인 → 모든 앱 → 앱 만들기.

이름 ‘부대 키우기’, 기본 언어 한국어, 유형 ‘게임’, 현재 무료 배포 계획이면 ‘무료’를 선택합니다. 무료/유료 선택은 향후 판매 계획까지 고려하세요. 문의 이메일은 실제 수신하는 주소를 사용합니다. 정책·수출·앱 서명 약관은 본인이 읽고 동의합니다.

일반 Android 개발자 신원 인증만 완료했고 Play Console 개발자 등록 자체는 아직이라면 먼저 콘솔의 등록 안내를 완료해야 합니다. 새 개인 계정에서 Android 기기 인증 항목이 나오면 실제 폰의 Play Console 앱으로 완료합니다.

## 5. 먼저 내부 테스트로 AAB 올리기

앱 → 테스트 및 출시 → 테스트 → 내부 테스트 → 새 버전 만들기.
Play 앱 서명 설정을 완료하고 위 AAB 1개를 업로드합니다. Google 관리 앱 서명 키를 선택할 수 있으며, 이 PC의 기존 키는 업로드 인증에 사용합니다. 키/암호 파일을 AAB 대신 올리지 마세요.

버전 설명 예시: ‘첫 테스트 버전입니다. 병력 성장, 지도 전투, 시작·홈·전투 음악, 볼륨 설정을 확인해 주세요.’
테스터에 본인 Google 계정을 추가하고 내부 테스트 링크로 설치합니다. 로컬 APK와 Play가 배포하는 앱의 서명이 다르면 업데이트 설치가 안 될 수 있습니다. 기존 저장을 지우기 전에 확인하세요. 내부 테스트 참여 기간은 아래 비공개 테스트 요건을 대신하지 않습니다.

## 6. 스토어 및 앱 콘텐츠 작성

대시보드의 미완료 항목을 순서대로 엽니다.

- 스토어: 소개 문구, 512px 아이콘, 1024×500 대표 이미지, 실제 화면 스크린샷 2장 이상, 문의 이메일, 카테고리.
- 개인정보처리방침: 3번에서 공개 접속을 확인한 URL.
- 앱 액세스: 별도 로그인·회원가입이 없습니다. 진급으로 콘텐츠를 여는 게임 진행 조건은 있습니다.
- 광고: 현재 배포 버전에는 광고 SDK나 실제 광고가 없습니다. 개발용 보상 버튼을 실제 광고로 신고하지 마세요.
- 데이터 보안: 현재 앱은 외부 서버로 개인정보를 수집·공유하지 않습니다. 기기 안 저장·오류 기록과 Android 백업은 방침을 참고하세요. 광고/통계/결제 SDK를 넣으면 이 답변을 다시 작성해야 합니다.
- 콘텐츠 등급: 픽셀 군사 전투가 있으므로 폭력 문항을 일괄 ‘없음’으로 답하지 마세요. 실제 표현을 기준으로 응답하고 IARC 결과를 확인합니다.
- 대상 연령: 실제로 서비스하려는 연령대를 선택합니다. 개발자가 정한 타겟과 심사로 정해지는 콘텐츠 등급은 서로 다릅니다.
- AI 에셋: 스토어에 새 이미지·영상을 올리는 흐름의 신고 항목을 자산별로 확인합니다. 소장 아이콘/이번 대표 이미지는 자체 코드 그림이며, 기존 시작 그림은 AI 생성입니다. 시작 그림을 포함한 스크린샷/영상은 해당 사실을 기준으로 판단합니다.
- 가격·국가·지역: 실제로 서비스할 곳을 선택하고 콘솔에서 추가로 요구하는 해당 지역 정보를 작성합니다.

## 7. 개인 계정이면 비공개 테스트 → 정식 출시 신청

2023-11-13 이후 생성된 **개인** 개발자 계정은 최소12명이 **연속14일** 참여 상태를 유지하는 비공개 테스트가 필요합니다. 테스터가 실제 설치·플레이하고 피드백을 줄 수 있도록 안내하세요. 요건 충족 후 테스트 내용과 준비 상태를 답변하여 프로덕션 접근을 신청합니다. 단순히 14일이 지났다고 자동 승인되는 것은 아닙니다.

조직 계정은 이 새 개인 계정 전용 조건이 그대로 적용되는 것은 아니며 계정 대시보드 안내를 따릅니다. 접근 승인 후 프로덕션 버전을 준비해 검토를 제출합니다. 지금 단계의 목표는 내부 테스트 업로드와 폰 확인, 이어서 비공개 테스트 시작입니다.
