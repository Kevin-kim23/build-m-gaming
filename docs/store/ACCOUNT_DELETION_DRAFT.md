# 부대 키우기 계정 삭제 안내 — 0.81.0 내부 초안

**게시용 최종본이 아니다.** 실제 운영 삭제 검증과 공개 요청 URL은 미완료다. 이 문서는 2단계의 코드 준비 내용과 삭제 범위를 맞추기 위한 내부 초안이다. 4단계에서 사용자가 게시할 최종 안내를 준비한다. 이번에는 공개 Google 방침이나 Play Console을 변경하지 않는다.

## 이용자에게 안내할 내용

부대 키우기(운영자 김동환·동람코)의 서버 계정 삭제는 Google 계정 자체를 삭제하지 않습니다. 서버에 직접 저장한 진행과 기기에만 있는 기록은 삭제 방법이 다릅니다.

- 앱을 이용할 수 있으면 **설정 → 구글 계정 연결 → 서버 계정·기록 삭제**에서 요청합니다. 다른 사람의 계정을 삭제하지 않도록 최근 Google 로그인이 필요할 수 있습니다.
- 앱을 이용할 수 없으면 현재 개인정보 문의 주소 **dong760630@naver.com**으로 계정 삭제 요청임을 알려 주세요. 요청 계정의 소유자인지 필요한 최소 정보로 확인하며, Google 비밀번호·인증 토큰·신분증 전체 사본은 요구하지 않습니다. 이 이메일 경로의 실제 접수·확인·처리·회신은 아직 운영 검증이 필요합니다.
- 삭제 대상은 Firebase 인증 계정, 게임 프로필·닉네임 소유권, 서버 게임 기록, 직전 백업·최초 연결 검토 기록입니다. 해당 계정이 신고자 또는 대상인 신고, 중복 신고 방지 정보, 관리자 처리·복원 기록, 미완료 정리 작업도 함께 삭제합니다. 탈퇴 계정의 일일 신고 집계와 서버 호출 제한 기록도 삭제합니다.
- 추후 랭킹이 추가되면 랭킹 연결 자료도 삭제 대상에 포함하여 검증합니다.
- 일부 삭제가 실패하면 완료라고 안내하지 않고, 재처리에 필요한 계정 식별자·요청 시각·처리 상태 등 최소 기록을 유지합니다. 실패 중인 요청을 일정 기간이 지났다는 이유만으로 지우지 않습니다.
- 모두 삭제한 뒤에는 **처리 확인 기록만 완료 후 90일** 보관하고 정리합니다. 반복 요청으로 90일의 시작점을 다시 잡지 않습니다. 게임 진행·닉네임·신고·관리 조치 자료를 탈퇴 후 90일 더 보관한다는 뜻은 아닙니다.
- 복원 전 기기 백업은 앱의 **이 기기의 복원 전 백업** 목록에서 확인한 항목만 개별 삭제할 수 있습니다. 보관 상한은 구버전 백업을 포함해 10개이며, 이미 상한을 넘은 백업도 말없이 지우지 않습니다. 개별 백업 삭제는 현재 진행 중인 기기 저장을 지우지 않습니다.
- **서버 계정 삭제만으로 기기 기록과 복원 전 백업은 지워지지 않습니다.** 기기의 모든 앱 기록을 삭제하려면 해당 기기에서 앱 데이터 삭제나 앱 제거를 별도로 해야 합니다. 이 경우 현재 진행과 기기 백업이 함께 사라질 수 있습니다. 단순히 백업 공간을 확보하려는 경우에는 필요한 백업을 남기고 개별 삭제 기능을 사용하세요.
- 운영체제 백업은 기기의 백업 서비스에서 별도로 관리해야 합니다. Firebase가 관리하는 인증 시스템·백업, Google 계정 자체·광고 정보에는 해당 서비스의 처리 기준이 적용됩니다. 게임 운영자가 모든 Google 정보의 즉시 삭제를 보장하지는 않습니다. 자세한 내용은 최종 개인정보처리방침에 연결합니다.

## 내부 삭제 대상과 보관 기준

| 자료 | 계정 탈퇴 시 처리 | 평상시 별도 보관 기준 |
| --- | --- | --- |
| nicknameReports | 신고자 또는 대상이 탈퇴하면 관련 문서 삭제 | 미처리는 검토 완료까지, 처리 원문은 완료 후 90일 |
| reportDedup | 신고자 또는 대상이 탈퇴하면 관련 최소 중복 방지 값 삭제 | 닉네임 변경 시 정리. 원문을 삭제해도 이름이 그대로면 중복 방지를 위해 유지 |
| reportDaily | 탈퇴한 신고자 UID의 일일 집계 삭제 | 다음 한국 시간 자정에 만료. 새 날짜 집계로 교체하거나 만료 작업으로 정리 |
| moderationActions | 신고자 또는 대상이 탈퇴하면 관련 처리·복원 기록 삭제 | 각 처리·복원 완료 후 90일 |
| moderationCleanup | 신고자 또는 대상이 탈퇴하면 관련 미완료 정리 작업 삭제 | 정리 성공 시 삭제. 실패 중에는 완료까지 유지하며 이름 원문·신고 사유는 저장하지 않음 |
| rateLimits | 탈퇴 계정의 서버 호출 제한 기록 삭제 | 만료 기준에 따라 정리 |
| deletions | 삭제를 끝내기 전까지 미완료 상태 유지 | 완료 확인 기록만 완료 후 90일 보관 |

프로필·닉네임 소유권·게임 저장·직전 백업·최초 연결 기록과 기존 랭킹 연결 자료도 삭제 서비스의 대상이다. 신고나 관리 자료가 많아 한 번에 모두 정리하지 못하면 삭제를 완료 처리하지 않고 다음 재시도로 이어간다. 관련 신고·관리 원문을 익명 통계라는 이유로 별도 복사하지 않는다.

삭제 완료 확인 기록의 90일과 신고·관리 기록의 90일은 서로 다른 자료에 적용되는 기준이다. 계정 탈퇴로 관련 자료를 지우는 절차가 우선하며, 평상시 신고 보관 기간이 남았다는 이유로 탈퇴 계정의 신고·처리 자료를 계속 보관하지 않는다.

예약 작업의 진행 위치에도 계정 UID나 신고 문서 식별자가 남을 수 있어 원본 삭제와 같은 트랜잭션에서 관련 참조를 지운다. 성공 삭제한 만료 문서는 시각만 진행 위치로 남기고, 실행 중 캐시에 있던 삭제된 ID를 체크포인트로 다시 저장하지 않는다. 삭제 완료 후 90일이 지난 UID를 작업 커서라는 이유로 추가 90일 보관하지 않는다. 전체 순회 종료 시 위치를 비우며 오래된 진행 위치는 다음 실행 때 초기화한다.

## 예약 실행 준비 상태

사용자는 **삭제 재시도 6시간마다, 만료 정리 하루 1번**으로 정했다. 닉네임 변경 후 남은 최소 중복 정보의 정리 실패도 재처리 대상이다.

현재는 예약 함수와 처리량·재시도 제한을 **코드로만 준비**했다. 실제 예약 작업, 개발·운영 서버 배포, 결제·예산·콘솔 설정은 적용하지 않았다. 삭제나 정리 서비스가 운영 중이라고 표시하지 않는다. 처리 실패 중인 삭제 요청과 최소 정리 작업은 완료될 때까지 유지하며, 완료 기록만 각 보관 기준에 맞춰 정리한다.

## 공개 전에 운영자가 확인할 것

1. 테스트 전용 계정으로 삭제 성공·부분 실패·재시도, 완료 후 90일 정리 경계, 신고자·대상 관련 전체 자료 삭제를 검증한다. 실제 이용자나 개발 만렙 계정으로 시험하지 않는다.
2. 계정 탈퇴와 신고·관리 조치가 동시에 일어날 때 자료가 다시 생기지 않는지, 부분 실패 후에도 삭제 요청이 남아 재처리되는지 확인한다.
3. 앱 없이 요청할 때 필요한 최소 본인 확인 방법, 담당자, 회신 절차를 실제로 운영 가능하게 정하고 공개 문안에 반영한다. 이메일 주소가 있다는 사실만으로 처리 체계를 완료했다고 하지 않는다.
4. 앱·개발자명, 삭제 방법·대상, 보관 자료와 기간을 포함하는 페이지를 공개한 뒤 로그인 없는 브라우저에서 확인한다. 현재는 게시할 웹 주소를 정하거나 공개 페이지를 만들지 않았다.
5. 확인한 실제 웹 링크를 Play Console의 계정 삭제 URL에 반영한다. 제출은 사용자 확인 후 진행한다. [Play 계정 삭제 요구사항](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ko)

실제 배포·예약 설정·운영 검증은 비용 추정 보고와 사용자 승인 후 별도 작업이다. 방침 11·약관 8 번호는 최종 문안 승인 전까지 유지한다. **정책 동기화 필요.**
