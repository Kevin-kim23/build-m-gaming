# 계정·서버 데이터 보안 처리 목록 — 1단계 작성 중 초안

2026-10-12. **Play Console 제출 답변이 아니다.** 운영 배포·실제 로그인/삭제 검증 및 신고 보관 기간이 아직 완료되지 않았으므로 4단계에서 최종 문안과 문항별 답변을 확정한다. 현재 방침11·약관8 번호를 유지한다. 공개 Google 문서는 사용자가 게시한다.

Play 양식의 데이터 유형 분류에서는 UID와 이메일, 닉네임, 게임 진행·신고, 보안 신호를 실제 SDK 안내 및 해당 문항과 대조한다. 서비스 제공업체에 위탁하는 전송은 Play의 공유 예외에 해당할 수 있지만, 이 이유만으로 수집 자체를 ‘없음’ 처리하지 않는다. 기기 안에서만 처리하는 백업은 서버로 전송하는 게임 저장과 구분한다. 최종 판단은 실제 배포본의 모든 포함 SDK와 트랙 범위를 확인한 후 한다. [Play 데이터 보안 작성 기준](https://support.google.com/googleplay/android-developer/answer/10787469?hl=ko), [Firebase Android SDK 안내](https://firebase.google.com/docs/android/play-data-disclosure).

## READ_GSERVICES와 Android 권한

이전 0.79.0 병합 Manifest에서 `com.google.android.providers.gsf.permission.READ_GSERVICES`가 reCAPTCHA 전이 의존성으로 확인되었다. 이 사실을 연락처·메일함을 읽는 기능이 있다고 바꾸어 설명하지 않는다. 반대로 Manifest의 직접 선언이 INTERNET 하나라는 이유로 병합된 SDK 권한을 누락하지 않는다. App Check 추가 후 **최종 AAB의 전체 권한 목록을 5단계에서 다시 추출**하고 실제 SDK 용도 및 데이터 처리와 대조한다. 지금은 최종 AAB를 생성하거나 검사했다고 표시하지 않는다.

## 4단계 전에 남은 항목

- 테스트 전용 계정으로 운영 로그인·저장·불러오기·삭제 및 실패 재시도를 확인한다. 기존 이용자/개발 만렙 저장을 운영에 업로드하지 않는다.
- 신고 보관·파기 기간, 운영 검토/이의제기 경로를 사용자와 확정한다. 자동 제재와 미정 닉네임 변경권을 도입하지 않는다.
- 공개 삭제 페이지의 실제 URL을 준비하고 비로그인 접속·신청·본인 확인·회신 절차를 검증한다. 로컬 Markdown/HTML이나 예상 URL은 공개 완료가 아니다.
- 국외 이전의 적용 근거·계약·고지/동의, Google과 운영자의 처리 구분을 최종 확인한다. Firestore 서울과 Firebase Auth 미국·App Check 글로벌 처리를 혼동하지 않는다. [Firebase 처리·위치 안내](https://firebase.google.com/support/privacy).
- 공개 방침·앱 문구·스토어 문서·Play 데이터 보안의 최종 수집/공유/선택·목적·삭제 답을 대조한 뒤 사용자가 게시/제출한다.

정책 동기화 필요. 이 문서는 개인정보 법률 검토, Console 제출, 공개 게시 완료의 증거가 아니다.
