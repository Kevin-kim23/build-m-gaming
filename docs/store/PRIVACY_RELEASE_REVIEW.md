# 정식 출시 개인정보처리방침 공개 전 확인 사항

2026-10-09 · 2단계 검토 기록 · 기준 코드 0.72.2

[정식 출시 방침 초안](PRIVACY_RELEASE_DRAFT.md)은 2단계의 검토용 문안이다. 3단계에서 확인된 운영자·문의·삭제·백업 안내를 개정6에 선별 반영하고 Google 공개 문서를 갱신했다. 아래 법적 확인 항목이 모두 해결된 것은 아니다. 실제 공개·배포 상태는 [동기화 상태](POLICY_SYNC_STATUS.md)를 따른다. 초안 파일을 새로운 방침 원본으로 계속 관리하지 않는다.

## 이번 단계에서 정리한 내용

- 기기 내 저장, Google 광고 처리, 운영자가 받는 문의를 구분했다.
- 정확한 나이와 생년월일을 서버에 보내는 것으로 오해하지 않도록 입력·저장·광고 제한 신호를 구분했다.
- 광고 거부·철회, 기기 기록 삭제, 운영자 문의 삭제, Google 데이터 권리 행사를 각각 설명했다.
- Android 백업이 남을 수 있어 앱 삭제를 모든 사본의 완전 삭제로 표현하지 않았다.
- 문의가 끝나 불필요해진 기록은 삭제하는 문안으로 작성했다. 현재 미구현 결제의 보존기간을 전체 문의에 일괄 적용하지 않았다.
- 정식 출시를 기준으로 작성했다. 테스터 이메일 관리는 이 초안의 중심에 포함하지 않는다. 진행 중인 테스트의 필요한 별도 안내·종료 시 목록 정리는 사라지는 의무가 아니며 별도 운영 항목이다.

## 공개 전에 해소할 항목

| 항목 | 현재 사실과 필요한 확인 | 해결 방법 |
|---|---|---|
| 운영자와 보호책임자 표시 | 사용자가 2026-10-09 담당자 성명을 김동환으로 확인했다. 초안에는 개인정보 보호책임자 김동환 및 확인된 문의 이메일을 반영했다. 동람코는 브랜드이며 아직 등록 사업자명으로 확정되지 않았다. 그 밖의 연락처 기재 요건은 확인이 남아 있다. | 사업자 등록 후 실제 운영 주체를 확인하여 표시를 갱신한다. 존재하지 않는 부서를 만들거나 사용자가 제공하지 않은 전화번호를 공개하지 않는다. |
| 문의 처리의 법적 근거 | 서비스 문의, 권리 행사, 향후 구매 분쟁은 목적과 적용 근거가 다를 수 있다. 메일 발송을 모든 수집·광고 처리의 포괄 동의로 취급하지 않는다. | 처리 목적에 맞는 동의 또는 다른 법적 근거와 적용 보존 의무를 확인한다. 필요한 경우 문의 접수 안내를 함께 보완한다. |
| 문의 계정 보안과 삭제 | 3단계에서 사용자가 혼자 문의 처리 및 불필요해진 메일·첨부파일 삭제 방식을 확인했다. 공개 업무 전화는 없다고 답했다. 실제 계정 보안 설정과 삭제 이력은 확인하지 않았다. | 4단계 운영 절차에서 확인·실행 후 안전조치 문구를 실제 상태로 확정한다. |
| 외부 처리 관계 | Google은 GDPR 안내에서 AdMob의 독립적 컨트롤러 역할과 일부 프로세서 기능을 구분한다. 이 설명만으로 한국법상 관계가 확정되지는 않는다. | 해당 AdMob 계약, 설정, 실제 SDK 처리를 검토한다. Google을 무조건 수탁자로 적거나 제3자 제공이 전혀 없다고 적지 않는다. 문의용 이메일 서비스도 확인한다. |
| 국외 처리 | 현재 안내는 Google 및 해외 서버 처리라는 일반 설명이다. 해당 법인·연락처, 국가, 유형별 기간, 적용 법적 근거가 미확정이다. | Google 공식 자료·계약·지원 답변을 통해 구체화하고 불명확한 국내법 적용은 전문가 또는 개인정보 상담으로 확인한다. 국가·기간을 임의로 채우지 않는다. |
| 선택 동의 화면 | 별도 광고 선택은 구현됐다. 하지만 선택 체크박스 하나가 제3자 제공·국외 이전 등 모든 법정 동의를 자동으로 충족하지는 않는다. | 위 처리 관계와 근거가 확정되면 필요한 고지·동의 구분을 `src/service-terms.js` 및 실제 화면에 반영하고 검증한다. 현재 선택 동의를 적법성 검토 완료로 표시하지 않는다. |
| 데이터 보안의 삭제 요청 답변 | 1단계에서 Console은 삭제 요청 방법 ‘아니요’였다. 방침은 문의 내용 삭제 요청을 안내한다. 서로 다른 처리 범위를 구분해야 한다. | 앱·SDK가 처리하는 데이터에 대해 실제 제공할 수 있는 삭제 경로를 확인한 후 문항별로 판단한다. 문의 이메일이 있다는 이유만으로 Google 데이터까지 삭제 가능하다고 신고하지 않는다. |
| 연령 신호 신고 | 정확한 나이는 기기에만 잠시 입력되지만 제한적 처리 여부는 SDK에 전달된다. | Google 데이터 유형 정의에 따라 이 신호의 추가 신고 필요성을 검토한다. 정확한 나이 미전송을 아무 연령 관련 신호도 전송하지 않는다는 뜻으로 쓰지 않는다. |

개인정보 보호법 제30조는 처리 목적·기간·파기·권리 행사와 함께 보호책임자 성명 또는 실제 고충 처리 부서 명칭 및 연락처 등의 기재를 요구한다. 현재 브랜드와 이메일만으로 충분하다고 확정하지 않는다. [공식 조문](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029332503)

국외 이전을 별도 동의에 근거해 처리하는 경우 제28조의8 제2항의 항목·국가·시기·방법·수령자·목적·기간·거부 관련 고지가 필요하다. 먼저 실제 관계와 적용 근거를 정해야 하며 Google 링크를 붙였다는 이유만으로 고지를 끝내지 않는다. [공식 조문](https://law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029332501)

Google의 독립적 컨트롤러 설명은 GDPR 맥락의 공식 설명이며, 한국법상 분류를 자동 결정하는 근거로 사용하지 않았다. [AdMob 공식 안내](https://support.google.com/admob/answer/7666366?hl=ko)

## 원본에 반영할 때의 순서

1. 위 공개 필수 항목을 확정한다. 문의·보안·삭제 약속이 실제 운영 가능한지 확인한다.
2. 출시 시점의 코드에 맞게 초안을 다시 읽는다. 결제 도입 시 구매 데이터와 관련 조건을 함께 반영한다.
3. 확정 문안을 `src/privacy-policy.js`에 반영하고 시행일·개정 번호와 `ACCESS_POLICY_REVISION`을 맞춘다. 광고 고지 변경에 따라 `AD_NOTICE_REVISION` 갱신 필요성을 판단한다. 네이티브 통신 프로토콜 상수는 문서 개정 번호로 바꾸지 않는다.
4. `npm run privacy:doc`으로 Markdown·HTML을 생성한다. 테스트와 웹 빌드를 수행하고 앱 버전·변경 기록을 갱신한다.
5. Google Docs 공개 본문과 Console 등록 주소·문항·스토어 설명을 대조한다. Google Docs 원문 변경이 공개 페이지에 반영됐는지 확인한다.
6. 새 앱을 빌드·배포하고 앱 내부 문안을 확인한다. 웹 방침 수정만으로 기존 설치 앱의 문구가 바뀌었다고 보고하지 않는다.

## 보류한 작업

- 유료결제와 사업자·결제 프로필: 사용자 일정에 따라 2026-10-12 이후 진행. 알림을 예약한 것은 아니다.
- 실제 광고 승인·공급·app-ads.txt 등: 사용자가 별도로 진행하기로 한 3번 작업. 초안 작성으로 광고 승인이나 수익 발생이 확인되는 것은 아니다.
- 4단계 운영 매뉴얼: 문의 접수·삭제·접근 관리·사고 대응 절차를 별도로 정리한다. 이 초안은 실제 보안 설정을 변경하지 않았다.

## 코드와 공식 자료 근거

- `src/privacy-policy.js`, `src/access-rules.js`, `src/access-ui.js`, `src/service-terms.js`: 현행 방침과 연령·광고 선택 흐름.
- `src/error-log.js`, `src/diagnostics.js`: 기기 내 오류 저장 및 이용자 직접 복사. 문의용 정보에 게임 저장 원문을 포함하지 않음.
- `android/app/src/main/AndroidManifest.xml`: 자동 백업 허용 및 초기 측정 지연 설정.
- `android/app/src/main/java/com/dongramco/budaekiugi/PotionAdsPlugin.java`: UMP·연령 보호·비맞춤형 요청.
- [Google Mobile Ads 25.5.0 데이터 공개](https://developers.google.com/admob/android/privacy/play-data-disclosure): 정보 유형·목적·TLS. 앱의 모든 처리를 대신 설명하는 자료는 아님.
- [Google 보관·삭제 설명](https://policies.google.com/technologies/retention?hl=ko): 데이터 유형에 따라 기간과 삭제 조건이 다름. 단일 보관기간으로 바꾸지 않음.
- [Google Play 사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=ko): 방침과 SDK 처리의 공개·일치 기준.
- [개인정보 포털](https://www.privacy.go.kr/): 개인정보 상담·분쟁 조정 연락처.

이 문서는 법적 준수 완료 확인서가 아니다. 공개 전 남은 항목을 해결하기 위한 검토 기록이며, 새 시행본 또는 Console 제출 완료를 의미하지 않는다.

2단계 검증 당시 테스트643개·웹 빌드 통과. 3단계는 테스트645개·웹 빌드·서명 AAB 검증 통과. 담당자 문구는 개정6의 앱 원본·Google 공개 문서에 반영됐다. 권한·SDK·광고 ID·게임 저장 스키마 변화 없음.

3단계 공식 자료 확인: Google 한국어 개인정보처리방침(2026-10-01 발효)에 googlekrsupport@google.com 문의 주소가 안내되어 개정6에 추가했다. 전 세계 서버 처리 안내를 특정 국가·단일 기간으로 바꾸지 않았다. [Google 방침](https://policies.google.com/privacy?hl=ko). AdMob 계약 법인은 계정의 약관에서 확인하라는 공식 안내가 있으므로 계약 상대를 임의로 확정하지 않았다. [계약 법인 안내](https://support.google.com/admob/answer/2772511?hl=ko)
