## A. 오늘 로그인 없는 AAB를 배포하기 전

- [ ] 배포할 실제 코드와 기능을 먼저 확정한다. 개발 브랜치라는 사실만으로 개발 기능이 AAB에서 빠지지는 않는다. build 모드·Android 변형·최종 파일을 검사한다.
- [ ] 공통 방침/약관에 남은 '개발용 로그인', 개발 기능 설명이 출시 사용자 안내에 섞이지 않도록 배포 범위에 맞게 정리한다. **0.77.1에서 구현·빌드 검증 완료.** 개발 빌드에는 실제 인증 처리 안내가 계속 필요하다. 환경별 문안을 관리한다면 같은 원본에서 생성하고 각각 테스트하여 수동 복사본이 어긋나지 않게 한다.
- [ ] 실제 존재하는 AdMob/UMP·문의 이메일 처리·OS 백업·연령/광고 선택 안내는 유지한다. 현재 release/debug 모두 샘플 광고를 쓰며, 테스트 광고도 통신/데이터 처리가 있다. 개발 로그인 제외를 '아무 데이터도 수집하지 않음'으로 바꾸지 않는다.
- [ ] 직전 공개 Google Docs 확인은 방침6이었다. 이후 방침7·8의 공개 반영은 미확인/미완료 기록이다. 이번에 공개 페이지를 다시 확인하고 실제 배포본에 맞는 최신 방침·시행일·문의처로 맞춘다. 과거 문서의 완료 표시는 당시 기준이다.
- [ ] 비공개 테스트와 운영 앱 중 현재 실제 사용자에게 제공되는 모든 버전의 처리를 고려해 Console 데이터 보안을 작성한다. 개발 PC에서만 시험하는 기능을 이미 모든 사용자에게 제공한다고 신고하지 않는다. 반대로 테스트 트랙에 계정 기능을 배포했다면 그 처리를 누락하지 않는다.
- [ ] 스토어 설명/앱 액세스/광고/대상 국가·연령/콘텐츠 등급이 해당 배포본과 맞는지 확인한다. 미래 닉네임·클라우드 복원·랭킹·유료 구매를 이미 제공한다고 적지 않는다.

| 앱 액세스/심사 | 로그인 없이 가능한 범위, 로그인 후 심사 접근 방법 | 심사자가 필요한 기능에 접근할 수 있고 개인 관리자 계정을 공유하지 않음 |
| 이용약관 | 계정/닉네임/저장/복구/제재/탈퇴/랭킹, 나중의 상품·환불·권한 복원 | 무료 테스트 문구·미래 기능 약속과 실제 서비스가 어긋나지 않음 |

Firebase 공식 안내상 인증용 IP 로그는 수 주간, 기타 인증 정보는 계정 삭제 시작 후 실제 시스템과 백업에서 180일 이내 제거된다. 이 기간을 게임 저장·구매 기록의 보유기간으로 그대로 복사하지 않는다. [Firebase 처리·위치·보유 안내](https://firebase.google.com/support/privacy).

한국 개인정보 보호법의 국외 이전 적용 근거는 실제 서비스/계약에 따라 확인한다. Google 로그인이나 서울 DB 선택만으로 검토가 끝나지 않는다. 별도 동의에 근거한다면 법정 고지 사항을 충족해야 하며, 다른 근거를 쓰는 경우에도 적용 요건을 확인한다. [개인정보 보호법 제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334743), [개인정보보호위원회 설명](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS292&mCode=C010050000&nttId=10972). 애매한 적용 판단은 전문가/관계기관 확인 대상으로 남긴다.

## C. 계정 삭제와 운영에서 놓치지 않을 것

- [ ] 외부 삭제 페이지는 실제 접속되는 URL이어야 한다. 앱/개발자 이름, 요청 방법, 삭제 대상, 남기는 자료와 근거/기간을 안내한다. 앱을 재설치해야만 요청할 수 있는 구조를 피한다. 이메일 접수 방식을 택하면 본인 확인·처리·회신 절차가 실제로 돌아가야 한다.
- [ ] Google 로그인만 사용해도 앱의 계정 생성/연결 방식이 Play 계정 삭제 요구에 해당하는지 확인하고 필요한 앱 안/밖 경로를 제공한다. 현재 Auth-only 개발 삭제를 전체 계정 삭제 완료로 표시하지 않는다. [Play 계정 삭제 요구사항](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ko).
- [ ] 공개 문의/책임자 연락처의 법적 충분성, 문의 처리 근거·메일 서비스 관계·보관/파기, 연령 보호 신호의 데이터 보안 분류는 기존 미해결 항목이다. [기존 최종 검토](PRIVACY_FINAL_AUDIT.md), [출시 검토](PRIVACY_RELEASE_REVIEW.md)를 이어서 확인한다.
- [ ] [개인정보 운영 매뉴얼](../PRIVACY_OPERATIONS.md)의 '기기에만 저장/운영자 서버 없음' 절차는 계정/서버 저장이 실제 도입되는 시점에 수정한다. 요청 처리·접근 권한·백업·사고 대응·제재/신고 담당을 실제 운영 가능하게 정한다.
- [ ] 서버 로그/모니터링을 추가하면 수집 필드·목적·보유기간·접근자를 명시한다. 인증 토큰·개인 사용자 저장·테스터 이메일을 공개 저장소에 넣지 않는다.

## D. 광고·실제 결제·자산·국내 출시의 남은 확인

- [ ] 광고: 현재 샘플 광고 유지와 정식 운영 광고 전환을 별도 작업으로 관리한다. 운영 전환 때 AdMob 승인/앱 준비/스토어 연결/app-ads.txt·UMP 설정·실제 게재를 확인한다. 광고 콜백 중복·취소·네트워크 오류에서 부당 지급/보상 누락을 시험한다.
- [ ] 광고의 국내법상 제공/위탁·국외 처리, 계약 법인과 실제 처리 국가·기간은 서로 다를 수 있다. 이전 조사에서 남은 항목을 이번 Firebase 추가로 해결됐다고 표시하지 않는다. [Google 처리 검토](GOOGLE_DATA_PROCESSING_REVIEW.md).
- [ ] 결제: Play Billing 적용과 현재 한국의 정책/허용 예외를 확인한다. 별도 외부 결제 링크를 임의로 추가하지 않는다. 상품 가격/효과·권한 지속·복원·환불/철회·미성년자 구매·사업자/판매자/세금 요건을 실제 판매 전에 확정한다. [Google Play 결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738?hl=ko), [수익화 체크리스트](../MONETIZATION_CHECKLIST.md).
- [ ] 테스트 지급/무료 보유 권한과 실제 구매 영수증을 구분한다. 사용자가 돈을 지불한 것처럼 표시하거나 로컬 보유값만으로 서버 유료 권한을 부여하지 않는다. 이미 지급된 무료 자동터치 영구 권한은 보존하되 서버 이관과 유료 영수증 검증은 구분한다.
- [ ] 라이선스: SDK 원문 고지, 자체/AI 그림·합성 효과음·Suno 음악·회사 오프닝의 출처·생성 당시 상업 이용 조건·증빙을 유지한다. 비공개 음원 원본/구매 증빙은 공개 Git에 올리지 않는다. [오프닝 자산](../OPENING_ASSETS.md), [라이선스](../licenses/README.md), [권리·법적 위험](LEGAL_RISKS.md).
- [ ] 상표/유사 디자인/실제 군 표식·오인 가능성, 스토어 이미지 사용 권리와 군사 폭력 표현에 맞는 등급 설문을 확인한다. AI 생성/자체 픽셀 제작만으로 권리 문제가 없다고 단정하지 않는다.
- [ ] 대한민국만 배포하는 설정, 개발자/판매자 신원·연락처·개인정보 공개 범위, 게임 등급과 사업/세금 관련 적용 요건을 정식 출시/수익화 시점의 공식 안내로 확인한다. 이 문서가 신고·등록을 대신하지 않는다.
- [ ] 사용자 기록상 10월10일22시경 테스터12명을 확보했다. 실제 연속 참여 인정·프로덕션 액세스 요건·심사 상태는 Play Console에서 확인한다. 코드 업데이트를 테스트 기간 완료나 출시 승인으로 간주하지 않는다. 이번 정리로 출시일을 새로 확약하지 않는다.
