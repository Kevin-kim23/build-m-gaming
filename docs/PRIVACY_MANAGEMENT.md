# 개인정보처리방침 관리 방법

> **절대 규칙: 개인정보·권한·SDK·광고·결제·외부 자산·콘텐츠 등급 답이 바뀔 때마다 (1) 앱 방침 원본과 docs, (2) 구글 독스 공개 방침, (3) Play Console 데이터 보안 양식·콘텐츠 등급·스토어 설명을 모두 최신화합니다.** AI는 (2)와 (3)을 직접 고칠 수 없으므로 작업 보고의 "정책 동기화 필요" 항목을 보고 사용자가 직접 고칩니다. 근거: AGENTS.md "정책·개인정보 동기화".

| 바뀐 것 | 고칠 곳 |
|---|---|
| 저장·수집 정보, 광고, 결제, 권한, SDK, 네트워크 | 방침 원본 → `npm run privacy:doc` → 구글 독스 → Play 데이터 보안 양식 |
| 폭력·도박·상호작용 등 게임 내용 | Play 콘텐츠 등급 설문 다시 제출 |
| 장비·시설·훈장 수 등 스토어 설명의 숫자, 새 기능 | Play 스토어 설명 |
| 음원·그림 등 외부 자산 | docs 출처 기록 + docs/store/LEGAL_RISKS.md |

법률 자문이 아닙니다. 아래 항목은 출시 전에 공식 문서와 전문가로 확인하세요. 제가 확인하지 못한 것은 "확인 필요"로 적었습니다.

## 1. 글이 있는 곳 (원본은 한 곳)
| 곳 | 역할 |
|---|---|
| `src/privacy-policy.js` | **원본.** 여기만 고칩니다. |
| 앱 안 "정보 → 개인정보처리방침 보기" | 원본에서 자동으로 보여줍니다. |
| `docs/store/PRIVACY_POLICY.md` | 원본에서 `npm run privacy:doc`으로 만든 문서. Play Console에 넣을 **공개 웹 주소**용입니다. |

Play Console에는 앱 안 글만으로는 안 되고 **누구나 열 수 있는 웹 주소**가 필요합니다. 저장소가 공개라면 GitHub Pages나 GitHub의 PRIVACY_POLICY.md 주소를 쓸 수 있습니다. (저장소를 비공개로 두면 주소가 안 열리니 주의. 확인 필요)

## 2. 고치는 순서
1. `src/privacy-policy.js` 글을 고친다.
2. `POLICY_DATE`(시행일)와 `POLICY_REVISION`(개정 번호)을 올린다.
3. `npm run privacy:doc` 실행 → 문서 갱신.
4. `npm test` (문서와 원본이 다르면 실패합니다.)
5. Play Console의 데이터 보안 양식과 웹 주소 글도 같은 내용으로 바꾼다.
6. 앱을 새 버전으로 올려 배포한다. 중요한 변경은 업데이트 설명에도 알린다.

## 3. 자동 경보
`tests/privacy-policy.test.js`의 마지막 테스트가 "수집 없음" 약속을 지키는지 감시합니다. 아래가 생기면 테스트가 **일부러 실패**합니다.
- 새 패키지(광고·결제 SDK 등) 추가
- 안드로이드 권한 추가
- 코드에 네트워크 요청·위치 사용 추가
실패하면 방침 글, Play 양식, 그 테스트의 허용 목록을 **함께** 고치세요. 허용 목록만 고쳐 테스트를 통과시키지 마세요.

## 4. 광고를 넣을 때 해야 할 일
- 광고 SDK는 보통 광고 ID(기기 식별자), IP, 기기 정보를 쓰고 SDK 회사가 처리합니다. 방침의 "수집 없음"은 **반드시 고쳐야 합니다.** 쓰는 SDK 회사의 개인정보 안내를 읽고 그대로 적습니다. (확인 필요)
- 방침에 적을 것: 어떤 SDK인지, 무슨 정보를 쓰는지, 왜 쓰는지, 누가 처리하는지, 국외 이전 여부, 거부·삭제 방법.
- Play 데이터 보안 양식: "광고 ID"와 "기기 또는 기타 ID" 수집·공유 항목을 체크하고 AndroidManifest에 광고 ID 권한을 선언합니다. (확인 필요)
- 동의 화면: 이용자 동의가 필요한 지역이 있습니다(유럽 등). 광고 회사가 제공하는 동의 도구를 쓰는 것이 일반적입니다. (확인 필요)
- 대상 연령: 어린이용으로 분류되면 광고·개인정보 규칙이 훨씬 엄격합니다. 어린이 대상이 아니라고 설정했다면 그에 맞게 운영해야 합니다.
- 보상형 광고는 보지 않아도 게임이 진행돼야 합니다.
- 이 저장소의 `rewarded-ads.js`는 지금 광고 없음 상태입니다. SDK를 붙이면 위 경보 테스트가 실패해 알려 줍니다.

## 5. 앱 내 결제를 넣을 때 해야 할 일
- Google Play 결제만 사용(앱 안 결제는 Play 규칙을 따라야 함). 결제 정보는 Google이 처리하며 게임은 카드번호를 받지 않습니다. 그래도 **구매 기록(어떤 상품을 샀는지)** 을 저장하면 방침에 적습니다.
- 서버 없이 결제를 확인하면 변조에 약합니다. 서버 검증을 쓰면 그 서버가 개인정보 처리자가 됩니다. (확인 필요)
- 한국 소비자 보호: 상품 설명·가격 표시, 환불 안내, 청약철회, 미성년자 결제 안내가 필요합니다. 사업자 등록·통신판매업 신고는 수익이 생기면 확인하세요. (확인 필요)
- 확률형 아이템(뽑기, 개인 장비 강화 확률 등)을 **유료로** 팔면 한국 게임산업법상 확률 공개 의무가 생깁니다. 유료와 확률 요소는 섞지 않는 편이 안전합니다. (확인 필요)
- Play 콘텐츠 등급 설문과 가격·상품 정책을 다시 작성합니다.

## 6. 계정·계약 쪽
- 개발자 이름·주소·이메일이 스토어에 공개될 수 있습니다.
- 방침의 문의 이메일은 실제로 읽는 주소여야 합니다. `PRIVACY_CONTACT`에 넣으세요. 비어 있으면 Play 스토어의 개발자 연락처로 안내합니다.
- 테스터 이메일 목록은 개인정보입니다. 보관 목적을 정하고 끝나면 지웁니다.

## 7. 해마다 점검
- Play 정책 변경 알림 확인, SDK 업데이트 때 안내 문서 재확인
- 방침 날짜가 1년 넘게 그대로라면 내용이 맞는지 읽어 봅니다.
