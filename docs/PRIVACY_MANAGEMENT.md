2026-10-09 · 0.72.3 · 방침 개정 6

앱 방침은 `src/privacy-policy.js` 한 곳을 원본으로 관리한다. 확정된 운영자·문의·삭제 안내를 개정6에 반영했다. 이번 개정은 처리 기능을 추가하지 않는다. 정식 출시 법률 검토가 모두 끝났다는 뜻은 아니다. 남은 항목은 [공개 전 확인 사항](store/PRIVACY_RELEASE_REVIEW.md), 실제 게시 상태는 [동기화 상태](store/POLICY_SYNC_STATUS.md)를 확인한다.

## 원본과 공개 위치

| 위치 | 역할 |
|---|---|
| `src/privacy-policy.js` | 앱과 생성 문서의 유일한 원본 |

| 이용자에게 배포한 앱 | 새 빌드를 설치해야 내장 방침도 갱신됨 |

## 바꿀 때마다 하는 순서

1. 실제 코드·SDK·권한·운영 방식에서 달라진 내용을 확인한다.
2. 원본과 시행일·개정 번호 및 방침 확인 버전을 맞춘다. 모르는 국가·보관기간이나 시행하지 않은 보안 조치를 지어내지 않는다.
3. `npm run privacy:doc`으로 Markdown·HTML을 생성한다. 생성 파일을 따로 고치지 않는다.
4. 광고 동의 안내와 약관의 영향도 검토한다. 문서 개정과 네이티브 광고 통신 프로토콜은 별개다.
5. `npm test`, `npm run build`를 수행한다. SDK·권한 허용 목록을 검토 없이 늘리지 않는다.
6. Google Docs를 같은 내용으로 갱신하고 로그인 없이 공개 URL의 본문·개정 번호를 확인한다.
7. Console 신고·스토어 설명을 대조한다. 필요한 항목만 수정하고 검토 제출·게시 상태를 기록한다.
8. 새 버전을 서명·배포하고 앱 안 방침을 확인한다. Git 푸시, 웹 방침 게시, Play 앱 배포는 각각 다른 완료 상태다.

## 계속 관리할 항목

- 문의 해결 후 불필요한 정보·사본을 삭제한다. 법정 보존이 적용되면 근거와 기간을 구분한다.
- 기기 기록, 문의 기록, Google 광고 데이터를 구분하여 권리 요청을 처리한다. Google 전체 데이터 삭제를 약속하지 않는다.
- [4단계 운영 매뉴얼](PRIVACY_OPERATIONS.md)에 문의·권리 요청·삭제·계정 보안·사고 대응 절차와 답장 예문을 정리했다. 네이버/Google 2단계 인증과 PC/휴대폰 잠금은 2026-10-09 사용자 확인 기준으로 켜져 있다. 설정 화면·실제 삭제 이력은 검사하지 않았다.
- 광고·결제·서버·SDK 또는 배포 국가가 바뀌면 방침·신고를 재검토한다. 과거 보고서는 당시 기록이다.
- 테스터 관리는 별도 한시적 업무다. 목록은 Console에만 있다는 사용자 확인이며 정식 출시 방침의 중심으로 다루지 않는다.
