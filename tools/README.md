# 저장·작은 화면 검증

`npm run qa:save` 실행 후 http://127.0.0.1:4198/__save-check 를 엽니다.
실제 플레이용 4173과 별도 저장 공간이며 4198에서만 테스트 기록을 만들 수 있습니다.
이 설정은 개발 서버 전용이고 앱 빌드에는 포함되지 않습니다.

1. **정상 원수** → 게임 확인: 320×568 / 390×844 화면에서 장군검·리볼버 이름, 사용 중 타이머, 배경 버튼이 겹치거나 잘리지 않는지 확인합니다. 버튼 높이는 44px 이상, 홈 가로 넘침은 없어야 합니다.
2. **손상 + 보조 복구** → 게임 확인: 복구 안내, 원수·큰 금액을 확인합니다. 저장 확인에서 `save.parse`의 원인 코드가 보이고 문의용 정보에 저장 원문이 없어야 합니다.
3. **둘 다 손상** → 게임 확인: 진행이 막히고 저장 확인 → 안내·문의용 정보 복사·저장 다시 확인이 보여야 합니다. 원본을 초기화하는 버튼은 없습니다.
4. **새 버전 기록**: 기존 보조 저장으로 되돌리지 않고 업데이트 안내와 진행 잠금을 확인합니다.
5. **주 저장 누락**: 남아 있는 보조 저장에서 원수를 복구해야 합니다.

자동 검사: `node --test tests/save-diagnostics.test.js tests/session.test.js tests/info-panel.test.js`.
금액·저장·이전 버전 호환을 포함한 전체 검사는 `npm test`, 출시용 웹 검사는 `npm run build`입니다.

손상 원본 보관 키는 `budae-kiugi-recruits-v3-recovery`입니다. 보조 저장으로 복구할 때 덮어쓰기 전에 최근 손상 원문 1개를 보관합니다. 이 공간에도 쓸 수 없으면 원본 교체를 중단합니다. 둘 다 손상됐거나 미래 버전이면 원래 저장을 그대로 두고 진행을 막습니다. 원문은 문의용 로그에 포함되지 않습니다. 이 보관 키는 자동 복원이나 과거 장비 수량 환급 기능이 아닙니다.
